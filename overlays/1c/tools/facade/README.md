# MCP-фасад для 1С

Один MCP-сервер вместо зоопарка: шесть глаголов наружу, маршрутизация,
резолвер имён и нормализация ответов внутри.

Статус: собран слой, который делает работу, — реестр, резолвер, карта здоровья,
шесть глаголов, нормализация. Не хватает обёртки: MCP-сервера, публикующего
глаголы наружу, и чекера правил за глаголом `check`.

## Зачем

В 1С-контуре несколько MCP-серверов с пересекающимися именами инструментов
(`codesearch` / `search_code` / `trace_call_chain` / `get_method_call_hierarchy`),
но с разной зоной компетенции. Пока выбор делает модель по тексту доктрины, она
регулярно уходит не туда: описания похожи, а разница видна только по качеству
ответа. Фасад переносит выбор из промпта в код.

Второе, ради чего он существует: сейчас «объекта нет», «индекс протух» и
«сервер выключен» дают одинаково пустой ответ. Блок `coverage` их разводит.

## Шесть глаголов

```
find(query, project, kind=any|routine|metadata|form|text, exact, limit)
describe(id, project, sections)
calls(id, project, direction=callers|callees, depth)
usages(id, project, where=metadata|code|both)
check(project, scope=staged|path|diff)
status(project)
```

`resolve` наружу не вынесен намеренно: резолвит каждый глагол сам, а
неоднозначность видна в `coverage.ambiguous`. Иначе вызывающая сторона обязана
помнить двухшаговый протокол — ровно то, от чего уходим.

## Маршрутизация — из замеров, не из вкуса

Замер на конфигурации в 446 модулей, эталон — grep по исходникам.

| Задача | Куда | Почему |
| --- | --- | --- |
| граф вызовов | `graph_metadata` | 8 из 8 против 2 из 8, и у второго ложный вызывающий |
| метод по имени | `code_metadata` | 0,1 с с полным телом против 4,9 с |
| объект метаданных | `code_metadata` | 0,1 с против 7,1 с |
| досье объекта | оба, слияние | досье подробнее, `code` добавляет типы реквизитов |
| использования объекта | оба, слияние | отвечают на разные вопросы: ссылки объект→объект против реквизитов с типом |
| использования **в коде** | grep | эталон 50 файлов, ни один индекс их не даёт |
| поиск по описанию | оба, союз | пересечение выдач 3%, союз почти вдвое полнее |

**Веер избирателен.** На поиске по описанию он почти удваивает полноту
бесплатно по времени — запросы идут параллельно, а выдачи почти не пересекаются.
На графе вызовов союз добавил бы известную ложную запись, на поиске метаданных —
семидесятикратную просадку ради ничего.

## Резолвер имён

Существует из-за измеренного дефекта: `code_metadata` матчит процедуру по голому
имени, поэтому `ОтправкаПочты` возвращает вызывающих *каждой* одноимённой
процедуры, а квалифицированная форма не возвращает ничего. Слить записи двух
бэкендов нельзя, пока канонический id не выбран **до** первого вызова.

Индекс строится из выгрузки конфигурации, а не из бэкенда: он обязан отвечать,
когда бэкенд лежит. SQLite, только стандартная библиотека, инкрементально по
SHA-256. Полная конфигурация в 446 модулей — 4123 символа за 0,4 с.

Неоднозначность не проглатывается: при нескольких кандидатах предпочитается
экспортный, а остальные возвращаются в `coverage.ambiguous`. Когда выбрать
нельзя — глагол честно отвечает списком кандидатов.

⚠ Экспортность определяется балансом скобок, а не окном фиксированной длины:
окна, достаточного для многострочного списка параметров, хватает и на то, чтобы
дотянуться до `Экспорт` следующей процедуры. На реальном корпусе это ровно один
метод из 242 — и однострочная регулярка его теряет.

## Карта здоровья и жизненный цикл

`status()` показывает состояние парка: отвечает ли бэкенд, поднят ли контейнер,
какого возраста индекс. Состояния `up` / `cold` / `down` / `unknown` различимы —
`cold` означает «контейнер есть, но остановлен», а не «объекта нет».

Индекс лежит в именованном томе, поэтому рестарт контейнера — инкрементальный
догон, а не пересборка. Фасад умеет поднимать бэкенд по обращению, но делает это
**только** там, где в реестре стоит `cold_ok`: будить чужое — побочный эффект, и
согласие на него фиксируется данными, а не кодом. `evict()` по LRU по умолчанию
работает вхолостую и требует явного запроса.

## Реестр

Одна запись на проект: путь к выгрузке, адреса бэкендов, имена контейнеров,
алиасы. Именно она заменяет десяток блоков в проектном `.mcp.json` — целевой
проект подключает один фасад, адреса знает фасад. Она же убирает угадывание
хоста по соседству.

Шаблон — `registry.example.json`; рабочий файл `facade-registry.json` или путь
в `FACADE_REGISTRY`, оба вне репозитория.

## Нормализованная запись

Всё, что отдают бэкенды, — сущность плюс необязательное ребро:

```
id      канонический квалификатор (от резолвера, не из эха бэкенда)
kind    metadata | module | routine | attribute | form | snippet
name, owner
loc     path (репо-относительный) + line/end
sig     сигнатура
rel     type (calls | called_by | references | referenced_by | typed_as | overrides)
        + to + depth + via
text    тело либо фрагмент
src     backend, tool, tier (indexed | live | grep), score
```

`src.tier` — не украшение: когда ответ пришёл из grep или из живого XML-скана, а
не из индекса, вызывающая сторона обязана это видеть.

Дубли сливаются **по полям**, а не выбором победителя: бэкенды дополняют друг
друга именно на уровне полей — один несёт расположение в файле, другой сигнатуру.

## Парсеры и защита от смены формата

`graph_metadata` отвечает форматированным текстом. Текст машинно-сгенерирован по
устойчивому шаблону, поэтому разбор — регуляркой: детерминированно, пиннится
фикстурами, стоит ноль.

Защита при обновлении образа — **детектор дрейфа**: каждый парсер сверяет число,
объявленное сервером в собственной шапке, с числом разобранных записей; для
досье — посекционно. Разошлось — гейт красный, и видно, какая секция уехала.

## Конвейер и гейты

```
python capture.py        # сырые ответы -> fixtures.local/ (вне репозитория)
python anonymise.py      # обезличенные -> fixtures/
python test_parsers.py   # парсеры: инварианты + снапшот
python test_facade.py    # резолвер, реестр, глаголы (на реплее фикстур)
```

`capture.py` берёт адреса из `FACADE_CODE_URL` / `FACADE_GRAPH_URL` — машинных
адресов в дистрибутиве нет.

`anonymise.py` обязателен: сырые ответы содержат префиксы объектов заказчика,
имя конфигурации и внутренние хосты в телах процедур. Отображение меняет
идентификаторы и вырезает тела, но не формат — а тестируется именно он; все
счётчики сохраняются, поэтому инварианты остаются осмысленными.

Гейты не требуют живых серверов: глаголы гоняются на клиенте-реплеере, резолвер —
на синтетической выгрузке в `fixtures/source/`. Корпус маленький, но
воспроизводит дефект, на котором держится вся конструкция: две процедуры
`ОтправкаПочты`, одна экспортная.

Расхождение «8 против 2» между бэкендами зафиксировано **как инвариант**. Если
поставщик когда-нибудь починит свой обход графа, гейт упадёт — и это правильно:
маршрутизацию придётся пересматривать, а не тихо жить со старой таблицей.

## Чего не хватает

- **MCP-сервер поверх глаголов.** Сами глаголы готовы; нужна публикация
  (FastMCP или руками по JSON-RPC) и `.mcp.json` в целевом проекте.
- **Чекер правил за `check`.** Глагол вызывает внешний CLI из
  `FACADE_CHECK_CMD` и честно сообщает, что чекер не настроен. Движок для него
  уже есть — `ci/check_layers.py` с реестром правил и режимом `--staged`;
  нужен второй набор правил по корпусу BSL/XML.
- **Офлайновая карта синонимов** «бизнес-термин → объект» для резолвера.
  Строится заранее и кэшируется. В тракте запроса внешних моделей быть не
  должно: недетерминированный шаг обесценивает гейт на фикстурах.
