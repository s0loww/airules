# MCP-фасад: слой нормализации

Статус: **спайк**. Готовы схема записи и парсеры под восемь форм ответов двух
бэкендов, с гейтом на фикстурах. Самого сервера ещё нет — см. «Чего не хватает».

## Зачем

В 1С-контуре несколько MCP-серверов с пересекающимися названиями инструментов
(`codesearch` / `search_code` / `trace_call_chain` / `get_method_call_hierarchy`),
но с разной зоной компетенции. Пока выбор делает модель по тексту доктрины, она
регулярно уходит не туда: описания похожи, а разница проявляется только в
качестве ответа.

Фасад убирает выбор из промпта в код: наружу шесть глаголов, внутри — таблица
маршрутизации, резолвер имён и нормализация ответов к одной форме.

## Почему маршрутизация именно такая

Таблица ниже — не предпочтения, а результат замера на одной конфигурации
(446 модулей), где эталон брался grep-ом по исходникам.

| Задача | Куда идти | Замер |
| --- | --- | --- |
| граф вызовов | `graph_metadata` | 8 из 8 против 2 из 8; у второго ещё и ложный вызывающий |
| метод по имени | `code_metadata` | 0,1 с с полным телом против 4,9 с |
| объект метаданных по имени | `code_metadata` | 0,1 с против 7,1 с |
| досье объекта | `graph_metadata` | заметно подробнее |
| использования объекта | оба, объединять | отвечают на разные вопросы: ссылки объект→объект против реквизитов с типом |
| использования **в коде** | grep | эталон 50 файлов, ни один индекс их не даёт |
| поиск по описанию | оба, объединять | пересечение выдач — 3%, союз почти вдвое полнее |

Два вывода, которые важнее самих чисел:

- **`code_metadata` матчит по голому имени метода** и не понимает
  квалифицированную форму (`Модуль.Метод` → пусто). Поэтому канонизация имени —
  обязанность фасада, а не бэкенда, и парсеры принимают `root_id` снаружи.
- **Веер оправдан не везде.** На поиске по описанию он почти удваивает полноту
  бесплатно по времени; на графе вызовов — добавляет ложную запись; на поиске
  метаданных — даёт семидесятикратную просадку ради ничего.

## Нормализованная запись

Всё, что отдают бэкенды, — сущность плюс необязательное ребро:

```
id      канонический квалификатор (резолвится фасадом, не берётся из эха бэкенда)
kind    metadata | module | routine | attribute | form | snippet
name, owner
loc     path (репо-относительный) + line/end
sig     сигнатура
rel     type (calls | called_by | references | referenced_by | typed_as | overrides)
        + to + depth + via
text    тело либо фрагмент
src     backend, tool, tier (indexed | live | grep), score
```

`src.tier` — не украшение: когда ответ пришёл из grep или из живого XML-скана, а
не из индекса, вызывающая сторона обязана это видеть.

## Парсеры

`graph_metadata` отвечает форматированным текстом, а не JSON. Текст
машинно-сгенерирован по устойчивому шаблону, поэтому разбор — регуляркой:
детерминированно, пиннится фикстурами, стоит ноль.

Защита от смены формата при обновлении образа — **детектор дрейфа**: каждый
парсер сверяет число, объявленное сервером в собственной шапке, с тем, сколько
записей разобрано. Для досье — посекционно. Разошлось — гейт красный, и видно,
какая именно секция уехала.

## Конвейер фикстур

```
python capture.py        # сырые ответы -> fixtures.local/ (в .gitignore)
python anonymise.py      # обезличенные -> fixtures/ (в репозитории)
python test_parsers.py   # гейт: инварианты + снапшот
```

`capture.py` берёт адреса из окружения (`FACADE_CODE_URL`, `FACADE_GRAPH_URL`) —
машинных адресов в дистрибутиве нет.

`anonymise.py` отображает идентифицирующие токены и вырезает тела методов.
Формат при этом не меняется, а именно он и проверяется; все счётчики
сохраняются, поэтому инварианты остаются осмысленными. Шаг обязателен: сырые
ответы содержат префиксы объектов заказчика, имя конфигурации и внутренние
хосты в телах процедур.

`test_parsers.py` держит две независимые линии: инварианты (числа, добытые вне
серверов) и снапшот (`fixtures/expected.json`). Первое ловит парсер, ошибающийся
согласованно; второе — дрейф формата.

Расхождение «8 против 2» между бэкендами зафиксировано **как инвариант**. Если
поставщик когда-нибудь починит свой обход графа, гейт упадёт — и это правильно:
маршрутизацию придётся пересматривать, а не тихо жить со старой таблицей.

## Чего не хватает

- **Резолвер имён** — словарь квалификаторов плюс офлайновая карта синонимов
  «бизнес-термин → объект». Строится заранее и кэшируется; в тракте запроса
  внешних моделей быть не должно, иначе гейт на фикстурах перестаёт что-либо
  значить.
- **Карта здоровья бэкендов** — сейчас «пусто», «сервер выключен» и «объекта
  нет» неразличимы для вызывающей стороны. Плюс запуск контейнера проекта по
  обращению: индекс переживает остановку, поэтому рестарт — инкрементальный
  догон, а не пересборка.
- **Сами шесть глаголов** — после парсеров и резолвера они тонкие.
