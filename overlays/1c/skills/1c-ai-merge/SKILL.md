# Plan a customized supplier update

Establish the requested outcome: inspect differences, prepare a merge plan or
apply a selected change. An inspection request does not authorize loading or
updating a configuration. Use the project's support/extension policies and
discover its actual artifact planner and project runners; a facade is optional.

Identify three inputs: the previous supplier baseline, current customized
configuration and new supplier version. Record artifact/revision identities,
source format, extension layer and coverage. Compare matching objects and
routines, not unrelated export layouts. A missing baseline, opaque artifact or
unmatched object leaves classification unresolved; do not manufacture a
three-way comparison from only two files.

Separate supplier-only changes, local-only changes, identical changes and
conflicts. Show the evidence and proposed treatment for each in-scope item.
Treat delete/rename, support state, borrowed metadata and changed signatures as
decisions requiring their own compatibility evidence, not just a text patch.

An extension/CFE proposal is one strategy where it fits the project. It does
not by itself complete a supplier update or prove that data migration works.
Check the availability and scope of object borrowing, interception and method
patching before proposing executable steps. Use the logical `extension-patterns`
and relevant metadata rules through the project's active index when needed.
Do not invent donor commands, an automatic MergeCfg route or a rollback command.

Keep the plan separate from application. A local manifest/hash comparison is
source-only evidence, even when its tool returns success. For an authorized
application, use the configured reviewed runner and saved plan with matching
source/target identities, test contour, platform build and fresh application
report. Session mode alone is not authorization for the requested mutation.

Verify the affected metadata/behavior with the existing pipeline and targeted
project tests. Report applied, proposed, blocked and unresolved items separately.
Preserve locks and unknown application state until supported reconciliation;
neither a CFE file nor an exit code proves live compatibility or restoration.
