Скопируй в `<outputRoot>/_build/DIAGRAM_SPEC.md`, заменив `<…>`. Ниже — вариант для двух
языков: `P` — ведущий язык (крупно), `S` — второй (мелко). Для одного языка убери всё про `S`.

# Контракт схем комплекта

Общие правила для всех схем archify. Схема — производная от кода, а не самостоятельный источник.

## Инструмент

- archify (желательно форк с полями узла `link` и `description`): `<путь к скиллу archify>`.
  Сначала прочитать его `SKILL.md` и идти по «Fast authoring path»: одна схема из `schemas/`
  под свой тип, `schemas/common.schema.json`, один пример из `examples/`. Для workflow новые
  исходники — `schema_version: 2`. Исходники рендерера до первого кандидата не читать.
- CLI: `node <archify>/bin/archify.mjs validate|deliver|visual-check …`
- Образцы оформления (если есть): `<готовые схемы проекта>` — раскладку и сюжет можно брать
  за основу, факты — нет, если это схемы проекта/плана, а не кода.

## Источник фактов

- Код: `<worktree>\<srcRoot>` (ветка `<ref>`, коммит `<head>`).
- Факт-файлы: `<outputRoot>\_facts\NN-*.md`. Каждое ребро и узел должны опираться на факт [V];
  при сомнении — открыть код по ссылке. [I]-выводы на схему не выносить как факт — только с
  пометкой «a verificar · требует проверки» (на языках комплекта).
- Имена и статусы: `_facts/inventory.json` (`name_<P>`, `name_<S>`, `changed`).

## Языки

- Узел: `label` — имя на `P`; `sublabel` — на `S`. Идентификатор 1С, если отличается от
  подписи, — первой строкой первого абзаца описания: `Objeto 1C: \`Tarja\``.
- `description`: сначала абзацы на `P`, затем те же по смыслу на `S`; каждый абзац — один язык;
  максимум 8 абзацев (до 4 пар), абзац ≤ 480 символов.
- Подписи рёбер / сообщений / переходов: `P · S`, коротко (≤ ~40 символов вместе). Не влезает —
  сокращать обе части, не удалять `S`.
- `meta.title`: `Название P · Название S`. `meta.views`: `label` — `P · S`, `note` — `P — S`.
- `cards`: заголовок `P · S`, пункты — сначала `P`, затем `S`.
- `meta.locale` — только если у рендерера есть локаль `P`; иначе не задавать (интерфейс
  просмотрщика и легенда останутся на английском — известное ограничение).
- Термины — по списку ключевых терминов из WRITER_SPEC; имена 1С — точно как в коде.

## Статус объекта — `tag` узла

`<new P> · <new S>` — объект создан проектом; `<modified>` — вендорский объект изменён;
`<core>` — вендорский без изменений; `<legacy>` — старый контур/режим, если в проекте есть
сосуществование моделей. Статус — из `inventory.json` (`changed`), не на глаз. Узел-группа —
статус центрального объекта, пообъектные статусы — в описании. В workflow / sequence / lifecycle,
где узлы — шаги/состояния, `tag` может нести ссылку на основание (`VD-38`, `A10`, `rango 3`).
У участников sequence поля `tag` нет — статус первой строкой описания.

## Жизненные циклы

Состояния lifecycle — только реальные значения перечисления статуса (сверить с `inventory.json`).
Ситуации риска («двойная отправка», «гонка») — не состояниями, а описанием перехода или
отдельным видом (`meta.views`) с явной пометкой, что это не статус.

## Композиция и приёмка

- `meta.quality_profile: "showcase"`; subtitle, visual_preset, legend, engineering_profile не задавать.
- ≤ 12 основных узлов, один очевидный главный путь; 2–4 `meta.views`.
- Двуязычные подписи длиннее — узлам `width` 170–230 и больший зазор между узлами.
- Вёрстка: без вертикальной прокрутки на 1440×900 (высота полотна к ширине ≲ 0.42–0.5;
  у lifecycle и sequence геометрия фиксирована — там допустимо больше, если прокрутки нет).
- Цикл: `validate --quality showcase --json` до 9/9 проверок, 0 ошибок, 0 предупреждений →
  `deliver` → `visual-check` → посмотреть PNG 1440×900 light (Read) и исправить явные проблемы
  читаемости, после правки — повторный `deliver`. Если после двух раундов точечных правок чистого
  прохода нет — остановиться и честно отчитаться диагностикой.
- Пересечения рёбер: сначала убрать малоценное ребро (описать связь в описании узла), потом
  двигать узлы; `via`/`labelAt` — только по диагностике.
- Уведомление archify о проверке обновлений — пропустить.
- Временные файлы — только с уникальным префиксом своей схемы (`bn08-validate.json`) или в
  своей подпапке scratch: параллельные агенты делят одну папку.
- Не трогать чужие файлы, не коммитить.

## Отчёт агента

Пути файлов; тип; итог validate (x/9, ошибки, предупреждения); sha256 и байты спецификации и
артефакта из `deliver`; код `visual-check` и смотрел ли PNG; узлы с `link` и `description`;
факты, в которых не уверен (`путь:строка`); что из факт-файла не подтвердилось кодом.
