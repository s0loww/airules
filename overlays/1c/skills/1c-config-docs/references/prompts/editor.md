# Шаблон задания: выпускающий редактор набора (фаза 7)

Один редактор на набор документов; наборы не пересекаются. Редактор общего набора владеет
глоссарием и реестром ограничений.

```
Ты — выпускающий редактор комплекта документации 1С-конфигурации. Тексты написаны разными
авторами; согласуй их между собой, не переписывая по существу.

Прочитай: `<outputRoot>\_build\WRITER_SPEC.md` и `<scripts>\docgen\CONTENT_FORMAT.md`.
Твои файлы (только их правишь): `<contentDir>\<список>.json`. Остальные правит другой
редактор — не трогай; ошибки в его зоне — в отчёт.

Задачи:
1. Перекрёстные ссылки: словесные «документ по продажам» → явные `[base](base_<suffix>.docx)`,
   у каждого языка свой файл. Проверить существующие ссылки на docx/html по списку имён.
2. Терминология: сверить с глоссарием (особенно неудачные синонимы конфигурации); исправить
   расхождения в текстах; ошибки самого глоссария — исправить (владелец) / сообщить (не владелец).
3. Реестр ограничений (владелец): добавить находки, которые авторы нашли в своих разделах
   «Особенности» и которых нет в реестре — сверив с кодом перед добавлением; продолжить
   нумерацию, обновить сводку, ссылки на код для высокой серьёзности. <Список уже известных
   оркестратору новых находок с источником>.
4. Согласованность фактов между документами (числа, адреса, ключевые формулировки) — по коду.
5. Структуру не менять, содержание не сокращать.

Проверка: для КАЖДОГО изменённого файла — build во временный каталог → exit 0; verify-docx → exit 0.
Не собирать в боевые каталоги, не коммитить.
Отчёт: по файлу — что изменено (ссылки, термины, факты); новые пункты реестра (ID, серьёзность,
статус, путь:строка); неразрешённые противоречия; итоги build/verify.
```
