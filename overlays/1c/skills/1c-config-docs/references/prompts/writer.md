# Шаблон задания: автор документа (фаза 6)

Агент: сильная модель — роль по таблице SKILL.md «Агенты и модели» (тексты на двух языках должны быть естественными).

```
Напиши ОДИН документ (<языки>) документации 1С-конфигурации <проект>. Контракт автора —
прочитай ПЕРВЫМ и соблюдай полностью: `<outputRoot>\_build\WRITER_SPEC.md` (формат, тон,
структура, термины, блоки diagram, проверка, отчёт).

Документ: id `<id>`, base `<base>`, set `<set id>`, title `{<P>: "…", <S>: "…"}`.
Содержание: <перечень тем 3–10 строк; чего в конфигурации НЕТ — сказать прямо и без оценок;
нормы права, не проверенные по коду — «требует проверки»>.
Схемы (блоки `diagram`): `<file>.html`, …
Факты: `<outputRoot>\_facts\<NN>-*.md` (основной), <смежные>; готовые схемы `<set>\*.json` —
их описания проверены по коду, сверяйся.
```

Особые документы:
- **91 реестр ограничений**: «Источник — §8 и §10 ВСЕХ факт-файлов; дубли слить; раздел
  безопасности и внешних интеграций первым; таблица ID | описание | последствие | серьёзность |
  подтверждено/проверить | объект | ссылка; не включать уже исправленные (сверь с реестром
  дефектов проекта); раздел решений, ждущих ратификации; ссылки на код для высокой серьёзности;
  документ внутренний». Удобно генерировать JSON маленьким скриптом с автонумерацией ID.
- **92 глоссарий**: «блоки `glossary` по разделам; термины, реально встречающиеся в конфигурации;
  где синоним конфигурации неудачен — корректный перевод и пометка в note; 150–300 терминов».
- **00 состав**: писать последним; таблицы документов и схем — из `meta.title/views` готовых
  JSON (генерирующий скрипт удобнее ручного переписывания — потом придётся синхронизировать).
- **Практическое руководство** (роли и операции): своя структура — роли и матрица прав, цикл
  работы пошагово по зависимостям в коде (кто, какой документ, что проверить до/после, типичные
  отказы и что делать), первичная настройка, частые проблемы «симптом → причина → действие».
