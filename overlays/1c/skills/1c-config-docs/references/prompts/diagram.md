# Шаблон задания: схема (фаза 4)

Агент: сильная модель — роль по таблице SKILL.md «Агенты и модели» (факты с кода + борьба с раскладкой). Одна-две схемы
одного участка на агента. Имя файла — из `_REGISTRY.md` набора.

```
Собери ОДНУ чистовую схему archify по <конфигурации / контуру> (итоговое состояние кода).
Параллельно другие агенты собирают соседние схемы того же каталога.

Прочитай ПЕРВЫМ и соблюдай полностью:
1. `<outputRoot>\_build\DIAGRAM_SPEC.md` — инструмент, источник фактов, языки, теги статуса,
   приёмка, формат отчёта.
2. `<set dir>\_REGISTRY.md` — имена соседних схем для `link`.
Известные дефекты на показанном пути: подтверждённые кодом ([V]) можно отметить в описании
узла; выводы [I] — только как «требует проверки».

Твоя схема: **`<prefix>NN-<name>.<type>`** (type <type>) — «<Название P · Название S>».
<Сюжет 3–8 строк: главный путь, узлы, что обязательно отметить (найденные в фактах нюансы),
какие связи — ссылками на соседние схемы: узел → `<file>.html`>.
Факты: `<outputRoot>\_facts\<NN>-*.md` (§§ …). Основа раскладки (если есть): `<проектная схема>`
(факты перепроверить). Подтверждать кодом.
Выход: `<set dir>\<name>.json` + `.html` (meta.output: `<относительный путь>`).
Отчёт — по формату из DIAGRAM_SPEC.md.
```

Условная схема (например, lifecycle статусов): «Делай ТОЛЬКО если в коде есть статусная модель
(реквизит-перечисление и переходы). Если нет — не делай и напиши почему» — либо «построй по
состояниям документа (записан / проведён / помечен) и честно скажи об этом в отчёте».
