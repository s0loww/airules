# Шаблон задания: аналитик участка (фаза 2)

Агент: аналитик 1С (если есть — с MCP-поиском по коду), сильная модель. Один агент — один участок.
Запускай все участки в одном сообщении.

```
Собери факт-файл о части 1С-конфигурации для последующей документации. Контракт — прочитай
ПЕРВЫМ и соблюдай полностью: `<outputRoot>\_facts\_SPEC.md` (источник кода — только
`<worktree>\<srcRoot>`, формат разделов §1–§10, ссылки путь:строка, метки [V]/[D]/[I], имена на
языках комплекта).

Твой участок: подсистемы **<A>** и **<B>** (состав — `Subsystems/<A>.xml`, `Subsystems/<B>.xml`
и вложенные). <2–5 строк: какие процессы и объекты сюда относятся, какие изменения проекта
учесть (пути к openspec/реестрам дефектов), какие соседние темы описать только как точку входа
(их разбирает другой аналитик)>.

Результат: `<outputRoot>\_facts\<NN>-<имя>.md`. Ничего другого не менять, не коммитить.
Отчёт (кратко): путь и размер файла, число процессов/объектов/отчётов, предложенные схемы,
главные находки §8, открытые вопросы.
```

Для особого контура проекта добавь: «КАК РЕАЛИЗОВАНО (не как спроектировано); план —
`<путь>` для контекста, расхождения с кодом записать в §8; карта сделанного — `<openspec changes>`».
