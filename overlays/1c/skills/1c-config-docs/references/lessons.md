# Грабли и лечение

Собрано из реального запуска (конфигурация ~1300 объектов, ≈60 агентов, 2 набора документов).
Каждый пункт: что случилось → чем это грозит → как не наступить.

## Источник и статусы

1. **Документировали не ту ветку.** Рабочее дерево пользователя было на ветке одного потока,
   итог — в ветке-интеграторе. → Всё описание устарело бы. → Фаза 0: найди ветку, в которую
   влиты остальные (`merge-base --is-ancestor`), подтверди у пользователя, создай worktree.
2. **Статус «доработан» у 81 % объектов.** Коммит «добавить русский язык интерфейса» задел
   2400 XML. → Теги на всех схемах врали, справочник показывал шум. → После инвентаризации
   смотри долю «доработано»; при >30 % ищи массовый коммит, включай нормализацию переводов
   (удалять `<v8:item>` нужного языка, сегменты `NStr` этого языка, концы строк). Нормализацию
   проверяй выборочно: объект только с переводами → «ядро», объект с правкой кода → «доработан».
3. **Первый поиск путей с кириллицей молчал.** git экранирует не-ASCII пути. → Объекты в
   папках с русскими именами выпадали. → `git -c core.quotePath=false … -z`.
4. **Висячие ссылки в составе подсистем** (GUID вместо имени) — это наследие выгрузки, не
   ошибка парсера. Выводи отдельным приложением справочника.

## Агенты и параллельность

5. **Лимит одновременных агентов** (20). → Лишние запуски падают. → Держи очередь и
   запускай по уведомлению о завершении; факты — сразу все, схемы — волнами.
6. **Общий scratchpad.** Агенты писали `v.json`, `d.json` в одну папку и читали чужие итоги
   проверки. → Ложные «прошло». → В каждом контракте: временные файлы только с уникальным
   префиксом или в своей подпапке.
7. **Команда проверки из контракта не работала** (`powershell -File verify-docx.ps1 a b`:
   массив путей приходит одной строкой, `$PSScriptRoot` пуст в 5.1, мусорные файлы с
   именами из аргументов). → Каждый автор искал обход. → В контракте только рабочая форма:
   `pwsh -NoProfile -Command "& ./verify-docx.ps1 -Path 'a','b' -Report '<file>'"`. Пробуй
   команду из контракта сам до рассылки.
8. **Отчёт агента ≠ факт.** Однажды в отчёте перепутались sha256 спецификации; агент «слышал»,
   что соседние схемы не проходят validate (проверял посреди их сборки). → Числа для README
   считай сам по файлам; итоговая сквозная проверка всех схем — обязательна.
9. **Хук-обёртки CLI обрезают вывод** (например, rtk для grep): поиск вернул пусто при реальных
   совпадениях. → Агентам: при подозрении на пустой результат перепроверять через полный путь
   утилиты.

## Схемы (archify)

10. **У участников sequence нет `tag`** — статус пишется первой строкой описания.
11. **Lifecycle и sequence имеют фиксированную геометрию**: колонки с постоянным шагом,
    минимальная высота; соотношение ≤0.42 недостижимо — это нормально, если нет прокрутки.
    Подписи на коротких рёбрах lifecycle физически не помещаются — смысл в номерах шагов и
    описаниях.
12. **Читаемость ограничивает ширину полотна**: при viewBox шире ~1240–1350 мелкий текст
    проецируется меньше 6 px на 1440 и validate падает. Не растягивай — сокращай.
13. **Карточки (`cards`) часто выталкивают страницу за 900 px** → убирать или сокращать до
    1–2 пунктов; содержание — в описания узлов.
14. **Пунктир на ребре в dataflow автолегенда называет «async batch»** — не используй пунктир для
    «дефектной» связи, только для реально асинхронной/ручной.
15. **Двуязычные подписи рёбер длинные** — закладывай зазор между узлами сразу, иначе
    каскад `labelAt`/`via`.
16. **Схемы проекта ≠ схемы кода.** Проектные схемы брать за основу раскладки, но каждый факт
    перепроверять: в реальном запуске отличий кода от плана нашлось по 5–16 на участок.

## Тексты

17. **Авторы не знали имён соседних документов** → ссылки словами → отдельный проход
    редактора. → Реестр имён документов — в WRITER_SPEC до запуска авторов.
18. **Термины разъехались** между авторами и схемами (приёмочная/тальманская ведомость,
    цессия/передача квоты, отгрузка для двух разных документов). → Список ключевых терминов —
    в WRITER_SPEC до запуска; глоссарий — источник истины; после — проход по схемам.
19. **Самые ценные находки появляются у авторов**, когда они вчитываются в свой участок
    (порядок закрытия, зависящий от языка сеанса; дыры в откате миграции). → В отчёте автора
    обязателен пункт «новые находки»; редактор переносит их в реестр ограничений.
20. **Авторы исправляют факт-файлы** (и иногда ошибаются: «база зависит от загрузки шаблона»
    опроверг редактор по коду). → Спорное — решает проверка кода, не большинство.
21. **Секреты в коде** (PIN-коды лицензий, пароли) не должны попасть в документацию.

## Сборка

22. **Картинки схем**: у archify нет CLI-экспорта PNG; скриншот `visual-check` содержит интерфейс.
    → `export-png.mjs` вызывает штатный экспорт просмотрщика через headless Chrome.
23. **Оглавление docx пустое до обновления полей** — в документе 00 и README сказать «ответить
    “Да” на вопрос Word». Open-check через Word заполняет его сам.
24. **HTML схемы может оказаться не от текущего JSON** (перезаписан чужим процессом). → Финал:
    повторный `deliver` во временный путь и побайтное сравнение.
25. **Экспортная копия**: только html + docx, относительная структура сохраняется, все ссылки
    проверяются внутри копии. Внутренние документы (реестр дефектов) — явно спросить или
    пометить при сдаче.

## Из прогона на расширении (контур БКИ, 129 объектов)

26. **Расширение ≠ конфигурация.** Статус «новый/доработан/ядро» бессмыслен: всё своё — новое,
    заимствованное — `Adopted`. Inventory теперь определяет режим сам; в фазе 0 — выяснить.
27. **Кириллица в именах** ломала якоря справочника и имена файлов. Исправлено (`safeAnchor`,
    Unicode в base); держи в наборе проверок скриптов кириллическую конфигурацию.
28. **Оркестратор неверно описал соседний каталог** в контракте («`src` — основная
    конфигурация», а это другое расширение). Выясни состав репозитория до контрактов.
29. **Старая документация — пересказ комментариев.** Сравнение с ручным комплектом: 9 из 24
    расхождений — ошибки ручного текста уже на его коммите, почти все из устаревших шапок
    модулей. Скилл выигрывает только потому, что проверяет по местам вызова — держи это правило.
30. **Авторы противоречат друг другу** (второй кандидат «падает вечно» / «закрывается тихо») —
    решает редактор по коду; в задании редактора перечисляй известные противоречия.
31. **Документ 00, запущенный параллельно с последним автором**, описал ещё не готовый 91 —
    генератор 00 перезапускать на финале всегда.
32. **Код выхода под пайпом теряется** (`node … | tail` → 0 при ошибке конфига).
