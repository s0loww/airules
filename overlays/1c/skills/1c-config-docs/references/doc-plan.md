# План комплекта: участки, документы, схемы

## Нарезка на участки (фаза 2)

Режь по подсистемам верхнего уровня (`Subsystems/*.xml`), сливая маленькие и выделяя тяжёлые.
Цель — 6–10 аналитиков, у каждого участок на 60–120 КБ фактов. Типовая раскладка для
учётной конфигурации:

| Участок | Что входит |
|---|---|
| Бухгалтерия | план счетов, регистр бухгалтерии, механизм проводок и определения счетов, закрытие периода, ОС, бюджет |
| Закупки и налоги | закупочные документы, налоговые удержания, НДС, электронные документы и их конвейер, налоговые отчёты |
| Продажи | заказы, счета, отгрузка, возвраты/ноты, расчёты с покупателями, экспорт со стороны продаж |
| Склад и производство | движения запасов, себестоимость, консигнация, производство, транспорт |
| Деньги | банк, касса, расчёты, чеки, сверка |
| Кадры и зарплата | договоры, табель, расчёт, взносы, налоги, выплаты |
| Платформа | разделение данных, сеанс, роли, ФО, регламентные, подписки, веб-сервисы, обмены, первый запуск, внешние сервисы, ИИ-функции |
| Особый контур (отраслевой) | 1–2 аналитика: он обычно самый новый и самый ценный |

Особый контур проекта (то, что делалось в проекте) выделяй в отдельный подробный набор.

**Технический / интеграционный контур** (обмен с внешней системой, конвейер обработки — часто
отдельное расширение с одной подсистемой): режь по **стадиям конвейера**, а не по подсистемам.
Пример (контур передачи кредитной истории, 129 объектов, 4 аналитика): захват изменений →
разбор и сборка → файл и обмен → эксплуатация (консоль, переключатели, задания, диагностика).

## Документы

Набор «вся конфигурация»:

| № | Документ | Источник |
|---|---|---|
| 00 | Состав документации: что, по какому коммиту, порядок чтения, таблицы документов и схем, условные обозначения, как пересобрать | все реестры; писать последним |
| 01 | Общая архитектура: подсистемы, статистика, разделение данных, сеанс, роли, ФО, регламентные, сервисы, внешние интеграции, первый запуск, языки | факт «Платформа» + §1 всех |
| 02–07 | По документу на участок | свой факт-файл |
| 08 | Обзор особого контура + навигация в подробный набор | факты контура |
| 90 | Справочник объектов (генерируется `reference.mjs`) | инвентаризация |
| 91 | Известные ограничения и дефекты (внутренний): безопасность и внешние интеграции первыми, серьёзность, подтверждено/проверить, ожидающие решения | §8, §10 всех + находки авторов |
| 92 | Глоссарий (для двух языков) | все факты + синонимы |

Подробный набор особого контура: 00 состав; 01 обзор и сквозная цепочка; 02–05 по звеньям
цепочки; 06 роли и практическая недельная/месячная работа (пошагово, типичные отказы, частые
проблемы).

Набор технического контура: 00 состав; 01 архитектура (назначение, состав, сквозной путь,
данные, настройки, интеграции, **глоссарий** — в одноязычном режиме отдельный 92 не нужен);
02–04 по стадиям; 05 эксплуатация (практическое руководство: консоль, переключатели, задания,
цикл оператора, диагностика «симптом → причина → действие»); 90 справочник; 91 ограничения.
Если у контура есть **норма/формат** (XSD, нормативный документ, таблицы кодов) — добавь
документ «Соответствие норме» и генерируемый справочник показателей (событие × сторона × блок ×
показатель — из XSD и таблиц): это то, чего код сам не объясняет, а аналитику нужно чаще всего.

**Два уровня чтения.** Каждый документ участка начинается с раздела «Коротко» (1–1,5 страницы:
что делает, главный путь, три главные особенности), подробные таблицы — дальше. Сравнение с
ручным комплектом показало: полный текст по коду в ~4,6 раза длиннее — без короткого уровня его
не читают.

## Схемы

Корневая схема каждого набора — `*-00-panorama.architecture`, её узлы ведут на все остальные.
На участок — 1–2 схемы по предложениям §9 факт-файла. Подбор типа:

| Сюжет | Тип |
|---|---|
| Что из чего состоит, откуда берутся проводки, роли и права | architecture |
| Путь данных по регистрам, слои учёта, откуда отчёт берёт цифры | dataflow |
| Пошаговый процесс с развилками: закрытие, оплата, миграция, настройка | workflow |
| Цепочка вызовов/обмена: э-документ до авторизации, ход ассистента, налоговая цепочка | sequence |
| Статусы документа и переходы | lifecycle |

Реестр `_REGISTRY.md` набора: файл | тип | сюжет | факт-файлы. Имена фиксированы — по ним
строятся `link` между схемами и `href` в документах.

Ориентир объёма реального запуска: 9 факт-файлов (≈1 МБ), 30 схем, 19 документов × 2 языка
(≈20–35 стр. каждый, справочник 359 стр.), ≈60 агентов, один рабочий день.
