# Скрипты скилла `1c-config-docs`

Все скрипты управляются **одним конфигом комплекта** (образец —
`../assets/docset.config.example.json`) и принимают `--config <путь>`; флаги CLI
переопределяют отдельные значения. Node ≥ 18. Зависимость одна — `docx` для генератора
документов: `npm i` в этой папке (`node_modules/` в `.gitignore`).

Общий контракт:

- **Коды возврата**: `0` — успех; `1` — находки (невалидное содержание, недостающие файлы,
  битые ссылки; то, что можно было записать, записано); `2` — ошибка выполнения, CLI или
  конфига (в том числе нет UI-строк для языка).
- **Отчёты** — машиночитаемый JSON у каждого скрипта (пути ниже).
- **Повторное чтение**: после записи скрипт перечитывает результат (размер/содержимое) и не
  доверяет собственному выводу.
- Какие скрипты пишут по умолчанию: основные (как исходные инструменты), `fill-png.mjs`,
  `callgraph.mjs`; `make-clear.mjs` пишет **только с `--apply`** (и удаляет только своё — по манифесту);
  `--dry-run` у `make-nav.mjs`, `fill-png.mjs` — только проверка. `check-lifecycle.mjs`, `verify-docx.ps1`, `opencheck-word.ps1` — только чтение
  (пишут лишь отчёт; `opencheck-word -Pdf/-OutDir` — ещё PDF).
- **Пробная сборка не трогает общие отчёты**: у `docgen/build.mjs` и `docgen/reference.mjs` с `--out`
  отчёт (и у справочника — JSON содержания) пишется в каталог `--out`, а не в `reportDir`/`contentDir`.

| Скрипт | Что делает |
|---|---|
| `inventory.mjs` | выгрузка конфигурации 1С (XML конфигуратора) → `inventory.json` + сводка |
| `callgraph.mjs` | места вызова экспортных методов общих модулей, ссылки на значения перечислений и константы → `callgraph.json` + сводка |
| `docgen/build.mjs` | JSON содержания → docx на каждый язык |
| `docgen/reference.mjs` | `inventory.json` (+ `purposes.json`) → справочник объектов (JSON содержания + docx) |
| `export-png.mjs` | PNG схем archify для вставки в docx (headless Chrome/Edge) |
| `fill-png.mjs` | поле `png` в блоках `diagram` содержания по PNG из `pngDir` (меняется только оно) |
| `check-lifecycle.mjs` | состояния lifecycle-схем против значений перечисления из `inventory.json` |
| `make-nav.mjs` | `index.html` + `README.md` каждого набора, контрольные суммы, проверка ссылок |
| `make-clear.mjs` | экспортная копия: index + html схем + docx, без `internalDocs`, все ссылки проверены внутри копии |
| `docgen/verify-docx.ps1` | независимая проверка docx: XML, структура, ожидаемые строки |
| `docgen/opencheck-word.ps1` | открыть docx в скрытом Word (COM), число страниц, PDF (`-OutDir` — в отдельный каталог) |

## Конфиг

Пути — абсолютные или относительно файла конфига (`outputRoot`, `source.*`); `factsDir`,
`pngDir`, `contentDir`, `reportDir`, `sets[].dir` — относительно `outputRoot`. Ключи,
начинающиеся с `$` или `_`, — комментарии; любой другой неизвестный ключ — ошибка (exit 2),
чтобы опечатки не проходили молча.

«Текст» ниже — строка (одинаковая для всех языков) или объект по кодам языков
`{ "<primary>": "…", "<secondary>": "…" }`; во всех объектах должны быть все настроенные языки.

| Поле | Обяз. | По умолчанию | Смысл | Кто читает |
|---|---|---|---|---|
| `project` | нет | — | Текст: название проекта | (справочно) |
| `source.worktree` | для inventory | `source.repo` | Рабочее дерево с выгрузкой (только чтение) | inventory, HEAD для коммита |
| `source.repo` | нет | — | Репозиторий (запасной для `worktree`) | inventory |
| `source.srcRoot` | нет | `src/main` | Каталог выгрузки внутри worktree | inventory, тексты справочника/README |
| `source.ref` | нет | — | Ветка/ref документируемого состояния; проверяется против HEAD worktree (предупреждение при расхождении); печатается в навигации | inventory, make-nav |
| `source.baseline` | нет | первый коммит, тронувший `srcRoot` | База сравнения (baseline) для статусов new/modified; в режиме расширения — для колонки «с базы сравнения» | inventory |
| `source.compareAlso` | нет | `[]` | Доп. ref'ы: поле `changed_vs_<ref>` у объектов | inventory |
| `source.commit` | нет | `git rev-parse --short=8 HEAD` worktree | Коммит на титулах docx (если в содержании нет `source.commit`) и в навигации | docgen, make-nav |
| `languages.primary` | **да** | — | `{code, suffix?, synonymFallback?}`: ведущий язык; `suffix` (по умолчанию = `code`) → `<base>_<suffix>.docx`; `synonymFallback` — языки синонима, если нет синонима ведущего | все |
| `languages.secondary` | нет | — | То же для второго языка; нет — **одноязычный режим** | все |
| `normalizeTranslations` | нет | `[]` | Коды языков, добавленные переводы которых не делают объект «изменённым» (XML `<v8:item>` этого языка, сегменты NStr) | inventory, текст справочника |
| `inventory.summaryLanguage` | нет | `en` | Язык `inventory-summary.md`: `en` или `ru` | inventory |
| `outputRoot` | **да** | — | Корень выходного каталога | все |
| `factsDir` | нет | `_facts` | Куда пишется инвентаризация и граф вызовов; здесь же необязательный `purposes.json`; строка же печатается в текстах | inventory, callgraph, reference, check-lifecycle |
| `buildDir` | нет | — | Отображаемый путь инструментов в сгенерированных текстах (`_build/inventory.mjs`, `_build/make-nav.mjs`); база для `reportDir` | reference, make-nav |
| `pngDir` | нет | `_png` | PNG схем | export-png, fill-png, README |
| `contentDir` | нет | `_build/docgen/content` | JSON содержания документов (`generated/` — генераторы) | docgen, fill-png, make-nav, make-clear |
| `reportDir` | нет | `<buildDir>/reports` или `_reports` | Отчёты `last-build.json`, `last-reference.json`, `make-nav-report.json`, `fill-png-report.json`, `make-clear-report.json`, `lifecycle-report.json` (сборка с `--out` пишет свой отчёт в `--out`) | docgen, fill-png, make-nav, make-clear, check-lifecycle |
| `sets[]` | **да** | — | Наборы документации (см. ниже) | docgen, export-png, make-nav |
| `reference.base` | нет | `90_Object_reference` | Имя файла справочника объектов (без суффикса языка); кириллица допустима — см. «Имена файлов и якоря» | reference |
| `reference.id` | нет | `object-reference` | `id` сгенерированного содержания | reference |
| `reference.contentFile` | нет | `generated/<base>.json` | Куда пишется содержание справочника (относительно `contentDir`) | reference, make-nav |
| `reference.set` | нет | первый набор | В какой набор кладётся справочник | reference |
| `reference.legacyNamePattern` | нет | — | Регэксп имени объекта → статус «устаревший» (`statusLegacy`) вместо «ядро»/«доработан» | reference |
| `reference.kindDetails` | нет | `true` | Таблицы свойств видов в главах справочника: подписки на события (источники, событие, обработчик), регламентные задания (метод, использование, предопределённое), константы (тип), общие модули (контекст выполнения, строк); `false` — прежний вид (байт в байт) | reference |
| `nav.readmeLanguage` | нет | ведущий язык | Язык `README.md` наборов | make-nav |
| `nav.toolLabel` | нет | `<buildDir>/make-nav.mjs` | Как называть генератор в подвале страницы/README | make-nav |
| `nav.rootDocPattern` | нет | `^00_` | Регэксп `base` документа «начать отсюда» | make-nav |
| `nav.rootDiagramPattern` | нет | `^<diagramPrefix>00-` | Регэксп имени корневой схемы | make-nav |
| `docgen.creator` | нет | `1c-config-docs docgen` | Поле «Автор» в свойствах docx | docgen |
| `uiStrings.<code>.<key>` | нет | встроенные `es`, `ru`, `en` | Переопределение UI-строк или новый язык (см. «UI-строки») | docgen, reference, make-nav |
| `archify` | нет | `archify` | Путь к `archify.mjs` для команд в README | make-nav |
| `clearCopy` | нет | — | Экспортная копия: путь относительно `outputRoot` (`_clear`, `../Base_logic_clear`); не может совпадать с каталогом набора или содержать его; упоминается в README | make-clear, make-nav |
| `date` | нет | сегодня | Дата документируемого состояния (титулы без `source.date`, навигация) | docgen, make-nav |

| Поле | Обяз. | Смысл |

| `lead` | нет | Текст: подзаголовок страницы |
| `navTitle` | нет | Текст: название набора на карточке «другой комплект» в других наборах (по умолчанию `title`) |
| `about` | нет | Текст: описание на этой карточке |
| `internalDocs` | нет | `base` документов «для внутреннего использования» (плашка на странице, пометка в README; `make-clear.mjs` не кладёт их в экспортную копию, если нет `--include-internal`) |
| `readmeIntro` | нет | Текст (на языке README): вводный абзац README |
| `staleWhen` | нет | Массив текстов: доп. пункты «когда комплект протухает» в README |

### UI-строки

Встроенная таблица (`lib/i18n.mjs`) для `es`, `ru`, `en`: подписи docx (язык версии на
титуле, «Страница N из M», «Содержание», «Рисунок», подсказка к оглавлению, «Интерактивная
схема», «Примечание»/«Внимание»), статусы `statusNew/Modified/Core/Legacy`, названия всех видов
метаданных 1С (`kinds.<Вид>` = `[ед., мн.]`), все тексты справочника объектов (включая режим расширения: `statusAdopted` и ключи `ext*`), страницы
навигации и README. `lang.<code>` — названия языков в грамматических формах этого языка
(для `ru`: `Name`, `nomM`, `adjN`, `genM`, `nomPl`, `prepPl`; для `es`: `name`, `Name`, `mPl`,
`fSg`, `fPl`; для `en`: `Name`). Строки — шаблоны с `{плейсхолдерами}`.

Переопределение: `"uiStrings": { "es": { "statusModified": "modificado" } }`. Новый язык —
`uiStrings.<code>` с полным набором ключей группы, которая нужна скрипту (docx — 13 ключей +
`lang.<code>.Name` для каждого настроенного языка; справочнику — ещё ключи `ref*`, `lbl*`,
`part*`, `status*`, `kinds`, а для выгрузки расширения ещё `statusAdopted` и `ext*`, при
`reference.kindDetails` — `kd*`, с `purposes.json` — `pur*`; навигации — `nav*`, `rm*`, `dateFormat`). Если строк нет или они
неполные — скрипт останавливается с кодом 2 и перечисляет недостающие ключи.

### Режим расширения (.cfe)

Включается сам, без поля конфига: если в `Configuration.xml` выгрузки есть
`ConfigurationExtensionPurpose`, выгрузка считается расширением.

- `inventory.json`: `header.extension = {name, purpose, namePrefix}`; у каждого объекта (и подсистемы)
  `belonging: "own" | "adopted"` — из `<ObjectBelonging>Adopted</ObjectBelonging>` в `Properties`
  (нет элемента — собственный объект расширения). У заимствованных объектов — `extensionAdds`:
  собственные реквизиты (включая `ТЧ.Реквизит` в заимствованной ТЧ), ТЧ, измерения, ресурсы, значения,
  формы/макеты/команды без `ObjectBelonging` и все модули объекта в выгрузке (`Ext/ObjectModule.bsl`,
  `Forms/<форма>/Ext/Form/Module.bsl` — в расширении модуль есть, только если расширение добавляет или
  перехватывает код); пустые ключи опускаются. У заимствованных элементов (реквизитов, ТЧ…) —
  `belonging: "adopted"`. Вне режима расширения этих полей нет (вывод прежний байт в байт).
- `changed` по git остаётся вторичным признаком «изменён с базы сравнения».
- Справочник: статус — «новый» (`statusNew`) для собственных и «заимствован» (`statusAdopted`,
  es «adoptado», en «adopted») для заимствованных, независимо от git; рядом колонка «С базы сравнения»
  (`extColSince`: «добавлен» / «изменён» / «—») в дереве подсистем и таблицах глав, два столбца-счётчика
  в таблице видов, строки «Расширение», «База сравнения», «Принадлежность» во введении, своя легенда и
  пояснение «Как вычисляется статус». Карточка заимствованного объекта: «Добавлено расширением: …» (или
  «заимствован без собственных элементов»), свойства вида (длина кода, проведение…) не печатаются —
  их задаёт основная конфигурация; заимствованные элементы помечены «· заимствован».
- `reference.legacyNamePattern` в режиме расширения действует только на собственные объекты.

### Имена файлов и якоря

- **Имена файлов** (`reference.base`, `base` содержания, `sets[].diagramPrefix`, ожидания make-nav) —
  одно правило (`fileBaseError` в `lib/config.mjs`): Unicode-буквы и цифры любого алфавита плюс
  `_ . -`, первая — буква или цифра; без пробелов и символов `<>:"/\|?*`, не на точку, не имя
  устройства Windows (`CON`, `PRN`, `AUX`, `NUL`, `COM1-9`, `LPT1-9`, в том числе `CON.docx`).
  `90_Справочник_объектов` допустимо. Нарушение в конфиге — exit 2, в содержании — exit 1.
- **Ссылки на такие файлы.** В docx относительная цель пишется как есть, в Unicode (проверено в Word:
  `Hyperlink.Address` = `90_Справочник_объектов_ru.docx`, файл находится; UTF-8 percent-encoding Word
  не декодирует), кодируются только пробел, управляющие и ``"<>^`{|}``. В `index.html` и `README.md`
  каждый сегмент `href` проходит `encodeURIComponent`, видимый текст — исходное имя; проверки ссылок
  декодируют href обратно.
- **Якоря** справочника (`safeAnchor` в `docgen/reference.mjs`, одна функция для заголовка и всех ссылок
  на него): имя из латиницы — `obj-<Вид>-<Имя>` / `ch-<Путь>` как есть (выход прежних комплектов не
  меняется); кириллица, `ñ` и т. п. — `<префикс><ASCII-транслит, ≤ 24>-h<8 hex sha1>`, например
  `ch-BL_R_ObmenSNBKI-hca907df1`. Имена 1С не содержат `-`, поэтому хешированный якорь не совпадёт с
  дословным. Закладка Word из якоря (`bookmarkId` в `docgen/lib/docgen.mjs`): `a_` + `[A-Za-z0-9_]`-слаг,
  обрезка до 30 + `_` + 8 hex sha1 = не длиннее 39 символов, с буквы; валидатор отвергает два якоря с
  одной закладкой.

## `inventory.mjs`

Разбирает XML-выгрузку конфигуратора (36 видов метаданных + дерево подсистем, без npm) в
`inventory.json`: синонимы по языкам (`name_<primary>` с запасными языками и именем 1С,
`name_<secondary>` или `null` — переводы не выдумываются), реквизиты, ТЧ, измерения/ресурсы,
значения перечислений, движения документов, состав подсистем и принадлежность объектов,
статус `changed` относительно базы сравнения (с нормализацией переводного шума) и `changed_vs_<ref>`;
для выгрузки расширения — `header.extension` и принадлежность объектов (см. «Режим расширения»).

```
node inventory.mjs --config <cfg.json> [--out <dir>] [--src-root <dir>] [--baseline <ref>]
```

- Выгрузка обязана быть в git (статусы берутся из истории): иначе exit 2 с рецептом
  (`git init; git add -A; git commit` — все объекты станут «ядром»). Ни одного разобранного объекта
  (не тот корень, EDT-проект `.mdo`) — exit 2. Папки видов, которые inventory не читает
  (`DefinedTypes`, `CommandGroups`, `DocumentNumerators`, …), перечисляются предупреждением.

- Конфиг: `source.worktree|repo`, `source.srcRoot`, `source.ref`, `source.baseline`,
  `source.compareAlso`, `languages.*.code/synonymFallback`, `normalizeTranslations`,
  `outputRoot` + `factsDir`, `inventory.summaryLanguage`.
- Выход (`<outputRoot>/<factsDir>/` или `--out`): `inventory.json` (в режиме расширения — ещё
  `header.extension`, `belonging`, `extensionAdds`), `inventory-summary.md` (для расширения — раздел
  «Расширение конфигурации»: счётчики собственных/заимствованных и что добавлено к заимствованным),
  `inventory-report.json` (HEAD, база, предупреждения — расхождение HEAD с `source.ref`,
  незакоммиченные изменения в `srcRoot`; находки — объекты, которые не разобрались).
- Коды: `0` — всё разобрано; `1` — есть неразобранные объекты (файлы всё равно записаны);
  `2` — нет выгрузки/worktree, ошибка git, ошибка конфига.

## `callgraph.mjs`

Граф вызовов для аналитиков: утверждения «вызывается», «используется», «никто не пишет» получают
опору на место вызова, а не на комментарий. Быстро (Эквадор: 1304 модуля, 235 тыс. строк — ~3 с) и
детерминированно; ключевые слова BSL русские и английские.

```
node callgraph.mjs --config <cfg.json> [--src-root <dir>] [--out <dir>] [--max-sites <n>]
```

- Читает все `*.bsl` выгрузки — общие модули, модули объектов, менеджеров, наборов записей, команд
  **и форм** — плюс XML подписок, регламентных заданий, перечислений, констант, форм и макетов.
  Перед поиском вызовов комментарии и строковые литералы затираются (номера строк сохраняются).
- **Экспортные методы общих модулей** (`Процедура|Функция|Procedure|Function Имя(…) Экспорт|Export`):
  файл:строка определения; места вызова — `Модуль.Имя(` из любого модуля (внешние), `Имя(` в своём
  модуле (внутренние), `Имя(` отовсюду для глобального модуля (локальная процедура с тем же именем
  перекрывает); ссылки метаданных (`Handler` подписки, `MethodName` задания); ссылки строкой
  (`"Модуль.Имя"`, `ОписаниеОповещения("Имя", Модуль)` / `NotifyDescription`). У каждого места — файл,
  строка, модуль (`DataProcessor.X.Form.Y`, `Catalog.X.ObjectModule`…) и объемлющая процедура.
- **Значения перечислений**: `Перечисления.X.Y` / `Enums.X.Y` в коде, `Перечисление.X.Y` / `Enum.X.Y`
  в текстах запросов и строках (`ЗНАЧЕНИЕ(…)`, `ПредопределенноеЗначение("…")`), псевдонимы
  (`Статусы = Перечисления.X;` … `Статусы.Y` — берётся ближайшее предшествующее присваивание в файле),
  `Enum.X.EnumValue.Y` и тексты запросов в XML (формы, макеты, СКД). Динамический доступ
  (`Перечисления.X[…]`, `Метаданные.Перечисления.X`) помечается у перечисления.
- **Константы**: `Константы.X.Установить(`/`.Set(` — запись, `.СоздатьМенеджерЗначения(`/
  `.CreateValueManager(` — запись через менеджер, `.Получить(`/`.Get(` — чтение, прочие `Константы.X` /
  `Константа.X` (поле запроса и т. п.) — «прочее», поле формы с реквизитом типа `ConstantsSet` —
  «ui» (чтение и запись через интерфейс).
- Выход (`--out`, иначе `<outputRoot>/<factsDir>/`): `callgraph.json` — `modules.<Модуль>.exports[]`
  (`counts` + места, не больше `--max-sites`, по умолчанию 200, на список), `unusedExports` (нет внешних
  мест, метаданных и строк; `internalCalls` — сколько вызовов внутри своего модуля),
  `metadataOnlyExports`, `enums.<X>.values.<Y>`, `unreferencedEnumValues` (с пометкой динамического
  доступа), `enumValuesOnlyInXml`, `constants.<X>`, `constantsNeverWritten`, `constantsNeverRead`,
  `constantsNotOnForms`, `problems`; `callgraph-summary.md` — те же списки таблицами (язык —
  `inventory.summaryLanguage`).
- **Ограничения** (оговаривать при ссылке на граф): не видны `Выполнить`/`Execute`,
  `Вычислить`/`Eval`, `ОбщегоНазначения.ОбщийМодуль("…")`, `ВыполнитьМетодКонфигурации`, метод через
  переменную с модулем, `Перечисления.X[Имя]` (только помечается), обход метаданных; псевдоним
  перечисления учитывается по файлу, а не по области видимости; выгрузка расширения видит только код
  расширения. «Нет мест вызова» — повод проверить, а не приговор: в факт-файле `[V]` ставится со ссылкой
  на найденное место, отсутствие вызова — с оговоркой о динамических вызовах.
- Коды: `0` — записано; `1` — часть файлов не прочиталась (остальное записано); `2` — ошибка
  конфига/CLI, нет выгрузки.

## `docgen/reference.mjs`

Справочник объектов: из `inventory.json` генерирует JSON содержания (введение, легенда
статусов, счётчики по видам, отсутствующие наименования второго языка — только в двуязычном

```
node docgen/reference.mjs --config <cfg.json> [--inventory <inventory.json>] [--purposes <purposes.json>]
                          [--out <dir>] [--content <file>] [--content-only] [--report <file>]
```

  `{ "<Вид>.<Имя>": "одна строка" | { "<язык>": "…" } }`, ключи на `$`/`_` — комментарии. В таблицах
  глав появляется колонка «Назначение» (после наименований); у объекта без назначения — «⚠ не описано»;
  во введении строка «Назначение объектов: описано у N из M»; список объектов без назначения — в stderr

- Конфиг: `reference.*`, `languages`, `factsDir`, `buildDir`, `source.srcRoot`,
  `normalizeTranslations`, `contentDir`, `sets`, `uiStrings`.
- Выход: JSON содержания — `--content`, иначе при `--out` — `<out>/<имя reference.contentFile>`, иначе
  `<contentDir>/<reference.contentFile>`; `<reference.base>_<suffix>.docx` в наборе `reference.set` (или
  `--out`); отчёт — `--report`, иначе при `--out` — `<out>/last-reference.json`, иначе
  `<reportDir>/last-reference.json`.
- Коды: `0` — собрано; `1` — ошибка валидации или вид объекта, которого нет в `KIND_ORDER`;
  `2` — нет/битый `inventory.json`, нет UI-строк (в т.ч. имени вида), ошибка конфига.

## `fill-png.mjs`

Подставляет PNG схем в содержание (фаза 8, после `export-png`): каждому блоку `diagram`, для базового
имени `href` которого есть `<pngDir>/<имя>.png`, ставит `"png": "<путь относительно файла содержания>"`.

```
node fill-png.mjs --config <cfg.json> [<content.json> ...] [--dry-run] [--report <file>]
```

- Файлы: перечисленные (от текущего каталога, затем в `contentDir`), иначе все файлы содержания

  что-то кроме `png`.

## `check-lifecycle.mjs`

Сверяет lifecycle-схемы с перечислениями: жизненный цикл = значения перечисления статусов, всё
остальное должно быть явно помечено.

```
node check-lifecycle.mjs --config <cfg.json> [<diagram.lifecycle.json> ...] [--inventory <inventory.json>]
                         [--enum <stem>=<ИмяПеречисления>]... [--report <file>]
```

- Схемы: перечисленные, иначе все `<diagramPrefix>*.lifecycle.json` наборов (без visual-check и `_`).
- Перечисление схемы: `--enum` > имена в `meta.title`/`meta.subtitle` > имена в первых строках описаний
  состояний `Объект 1С: …` / `Objeto 1C: …` / `Object 1C: …` (`Перечисление.X.Y`, `Enum.X.Y`,
  `Enumeración.X.Y` или имя перечисления в `` ` ``) > перечисление, чьи значения совпали с метками
  большинства состояний (не меньше двух). В `meta` archify свободных ключей нет
  (`additionalProperties: false`), поэтому подсказка пишется в `meta.subtitle`.
- Состояние = значение, если первая строка описания называет `<Перечисление>.<Значение>` или метка
  (или id) совпадает с именем/синонимом значения на любом языке выгрузки (без учёта регистра, «ё»/«е»,
  пробелов и знаков).
- **Соглашение о пометке** не-статусов (риски, ситуации, псевдосостояния): `tag` состояния содержит
  `riesgo` / `риск` / `risk` **или** id начинается с `risk-`. Состояние `type: "start"` — точка входа,
  пометки не требует.
- Находки: **ошибка** — состояние не значение перечисления и само об этом говорит (в метке, подписи,
  названии дорожки или первой строке описания: «риск», risk, riesgo, «не статус», "not a status",
  "no es un estado", «не значение перечисления», pseudo), но пометки нет; **предупреждение** — прочие
  не-значения без пометки (ситуация, нарисованная как статус?), значение перечисления с пометкой риска,
  значения перечисления, которых нет на схеме, схема без опознанного перечисления.
- Отчёт — `<reportDir>/lifecycle-report.json` (или `--report`): по схеме перечисление и как оно найдено,
  класс каждого состояния (`enum`, `marked-risk`, `entry`, `unmarked`, `violation`), недостающие значения.
- Коды: `0` — ошибок нет (предупреждения допустимы); `1` — нарушено соглашение о пометке или схема не
  читается; `2` — ошибка конфига/CLI, нет `inventory.json`.

## `make-nav.mjs`

Для каждого набора пишет `index.html` (самодостаточная страница: ведущий язык — основной
строкой, второй — мелкой строкой; в одноязычном режиме — один язык) и `README.md` (на
`nav.readmeLanguage`: реестр документов и схем, контрольные суммы SHA-256, команды
пересборки с этим конфигом, «когда протухает», «что кому отдавать», ограничения формата).
Проверяет HTML на корректность и отсутствие внешних ресурсов, все ссылки страницы и README,
переходы между схемами (`link` в JSON схем), затем перечитывает записанное.

```
node make-nav.mjs --config <cfg.json> [--dry-run] [--force] [--date YYYY-MM-DD] [--report <file>]
```

- Чужие `index.html` / `README.md` в каталоге набора (в них нет `make-nav` — например, README
  проекта при `dir: "."`) не перезаписываются: exit 2, в `--dry-run` — предупреждение. `--force` —
  осознанная перезапись.

- Ожидаемые документы набора — файлы содержания (`contentDir` и `generated/`), чей каталог
  вывода — каталог набора; для каждого нужны docx всех языков. Ожидаемые схемы — список из
  `_REGISTRY.md` набора (строки таблицы вида `` | `bl-…` | ``), а без него — все
  `<diagramPrefix>*.json`; для каждой нужны `.json` и `.html`. Названия схем — `meta.title`
  («Ведущий · Второй»), виды — `meta.views[].label`.
- Конфиг: `sets[]` (все поля), `source.ref/commit`, `date`, `languages`, `contentDir`,
  `reference.*`, `nav.*`, `factsDir`, `pngDir`, `archify`, `clearCopy`, `uiStrings`, `reportDir`.
- Выход: `<set.dir>/index.html`, `<set.dir>/README.md`; отчёт `<reportDir>/make-nav-report.json`.
- Коды: `0` — всё на месте, HTML корректен, битых ссылок нет; `1` — чего-то не хватает или
  проверка не прошла (страницы всё равно записаны, недостающее показано как «нет файла»);
  `2` — ошибка выполнения/конфига.
- Рендеринг и проверки — `lib/nav.mjs` (общие с `make-clear.mjs`).

## `make-clear.mjs`

Экспортная копия комплекта — то, что читатель открывает без репозитория.

```
node make-clear.mjs --config <cfg.json> [--dest <dir>] [--include-internal] [--allow-excluded-links]
                    [--apply] [--date YYYY-MM-DD] [--report <file>]
```

- Куда: `--dest`, иначе `<outputRoot>/<clearCopy>`. Каталог копии не может совпадать с `outputRoot` или
  каталогом набора и не может их содержать (иначе удаление устаревших файлов задело бы исходники) — exit 2.
- Что, по каждому набору, по тому же пути относительно `outputRoot` (структура между наборами сохраняется):
  `index.html`; схемы `<diagramPrefix>*.html` (без `*.visual-check.*` и `_`-файлов); docx документов набора
  (файлы содержания, чей каталог вывода — каталог набора). Документы из `sets[].internalDocs` не
  копируются, если нет `--include-internal`. JSON, README, PNG, `_facts`, `_build` не копируются.
- `index.html`: если из набора ничего не исключено — копия исходного файла байт в байт; иначе
  перерисовывается тем же рендерером, что у `make-nav` (`lib/nav.mjs`), **без исключённых документов**
  (и без плашки «для внутреннего использования»). README в копию не кладётся — противоречия «README
  велит не отдавать, а копия отдаёт» нет.
- Проверки: все относительные ссылки копии разрешаются внутри копии — `href` страниц index (docx, схемы,
  index других наборов), ссылки, вшитые в HTML схем (`data-*-link`, `href`, `src`), внешние цели связей
  (`*.rels`, `TargetMode="External"`) каждого docx (docx → docx, docx → html); внешние (`https:` и т. п.) не
  проверяются, считаются. Каждый файл после копирования перечитывается и сравнивается побайтно с
  источником (перерисованный index — с отрисованным текстом). Ссылка на **исключённый** документ
  (например, 01 → 91) считается отдельно: находка (exit 1) — у получателя она битая; `--allow-excluded-links`
  переводит её в предупреждение, когда это принято осознанно. Лечится в содержании (не ссылаться на
  внутренние документы из внешних) или `--include-internal`.
- **Без `--apply` ничего не пишется** (план, устаревшее и проверка ссылок — только отчёт; `--dry-run` —
  явное написание того же умолчания). `--apply` пишет копию.
- Владение: рядом с копией (не внутри) лежит манифест `<dest>.make-clear-manifest.json` — что записано
  прошлым `--apply`. Удаляются **только** файлы из манифеста, которых больше нет в плане (и опустевшие
  после этого каталоги). Любой другой файл в каталоге копии не трогается и считается находкой («foreign
  file»). Непустой каталог без манифеста, где есть что-то сверх плана, — отказ (exit 2): он не наш.
- Отчёт — `--report`, иначе `<reportDir>/make-clear-report.json` (с `--dest` — `<dest>.make-clear-report.json`):
  файлы с источниками, исключённые, удалённые, ссылки (`checked`, `ok`, `broken`, `toExcluded`, `external`).
- Коды: `0` — копия полная, все ссылки разрешаются, байты совпадают; `1` — нет исходного файла, битая
  ссылка, ссылка на исключённый документ (без `--allow-excluded-links`), расхождение байтов, некорректный
  index; `2` — ошибка CLI/конфига/выполнения.

## `docgen/verify-docx.ps1`

Независимое чтение готовых docx: распаковка в памяти, разбор всех `word/*.xml` как XML,
счётчики (абзацы, таблицы, заголовки, закладки, внутренние ссылки, картинки, поле TOC,
ориентация секций, слова, оценка страниц), поиск ожидаемых строк. Проверяет, что каждая
внутренняя ссылка (`w:hyperlink/@w:anchor`) попадает в закладку, а имена закладок уникальны и
по правилам Word (≤ 40 символов, с буквы, `[A-Za-z0-9_]`) — иначе exit 1 (`brokenIntLinks`,
`badBookmarks`); относительные цели внешних ссылок ищутся рядом с docx (предупреждение, не
ошибка). Только чтение.

```powershell
./docgen/verify-docx.ps1 -Path a.docx,b.docx [-Expect 'строка 1','строка 2'] [-Report out.json]
```

Отчёт — `-Report` (по умолчанию `last-verify.json` в текущем каталоге). Коды: `0` — всё
корректно и строки найдены; `1` — битый XML, нет части или строки; `2` — ошибка выполнения.

## `docgen/opencheck-word.ps1`

Открывает docx в скрытом MS Word (COM, только чтение), обновляет оглавление в памяти,
сообщает число страниц по Word, по `-Pdf` экспортирует PDF рядом с docx, по `-OutDir <dir>` — в этот
каталог (создаётся; `-OutDir` включает `-Pdf`; два docx с одним именем — отказ, exit 2). `-OutDir`
держит PDF вне боевых каталогов и экспортной копии. docx не сохраняет; по таймауту завершает только
свои процессы WINWORD (по PID).

```powershell
./docgen/opencheck-word.ps1 -Path a.docx [-Pdf] [-OutDir <dir>] [-TimeoutSec 600]
```

Коды: `0` — всё открылось; `1` — файл не открылся; `2` — ошибка выполнения или таймаут.
