# airules

**airules** — чистый дистрибутив методологии AI-разработки: правила, роли,
роутинг моделей и раскладка, собранные в переносимую слоистую модель. Текущая
стабильная раскладка — Claude Code; Codex и DSH/DeepSeek поддерживаются отдельными
target-адаптерами, а не форками правил.
Это **не форк** какого-либо рабочего репозитория правил — это новый проект,
куда каждый артефакт попадает только пройдя входной фильтр сорта: практика
включается в дистрибутив, если она действительно переносима, а не потому, что
она уже где-то написана.

## Слоистая модель

Дистрибутив разделён на слои по степени переносимости и собирается вместе с
профилем получателя и target-адаптером:

- **`core/`** — generic-метод без доменной специфики: роутинг ролей и моделей,
  контракты скриптов, принципы делегирования, структура agent definition.
  Переносится в любой проект любого стека.
- **`overlays/<stack>/`** — специфика технологического стека (не проекта).
  Переносится между проектами одного стека.
- **`project-layer/common/`** — общий распространяемый проектный слой:
  нейтральный контракт проекта, тестовый контур и defaults композиции.
- **`profiles/`** — профиль получателя: `public` для нейтральной раздачи и
  `s0lo` для локальной топологии возможностей без URL, путей и секретов.
- **`targets/`** — адаптер среды выполнения. Меняет формат раскладки, но не
  смысл собранной политики.
- **`project-template/`** — шаблон проектного слоя: описывает, что остаётся в
  целевом проекте и никогда не попадает в дистрибутив (пути, доменные имена,
  креды, память).

Отдельно от слоёв лежит **`services/`** — сервисы, которые запускаются на машине
и обслуживают все проекты сразу; в целевой проект они не устанавливаются
([`services/README.md`](services/README.md)).

Полные определения слоёв и входной фильтр — в [`docs/LAYERS.md`](docs/LAYERS.md),
порядок сборки — в [`docs/COMPOSITION.md`](docs/COMPOSITION.md).

## Синхронизация

Codex-слой собран в основном репозитории с учётом работы отдельного порта:
[`targets/codex/README.md`](targets/codex/README.md). Он использует актуальные
`core/` и `overlays/`, проектный слой и профиль получателя. Навыки раскладываются
в `.agents/skills/`, роли — в `.codex/agents/*.toml`; MCP остаются проектными.
Статус target — experimental: сборка и приёмка на фикстурах отделены от запуска
реальных моделей, MCP и проверок 1С.
Состав, результаты и границы готовности: [CODEX-INTEGRATION.md](docs/CODEX-INTEGRATION.md).

Модель распространения — **релизы + манифест установки**: дистрибутив живёт в
этом репозитории, версии помечаются git-тегами и файлом `VERSION` (semver).
Агент-инсталлятор копирует выбранные слои в целевой проект и записывает
`.airules-manifest.json`, по которому потом выполняется безопасное обновление.
Подробности — в [`docs/SYNC.md`](docs/SYNC.md).

## Чистота слоёв

Чистота слоёв контролируется CI: скрипт `ci/check_layers.py` ищет утечки
кредов (включая эхо пароля в вывод), машинных путей (драйв-корни, UNC,
POSIX), доменных имён, стековых терминов в ядре, хардкода моделей вне
`model-map.yaml`/`model-profiles.md`, верхней ступени усилия (`max`) без
маркера эскалации, снятых формулировок самоперепроверки и отсутствие UTF-8
BOM в `*.ps1`. Полный перечень — `docs/LAYERS.md`.
Проверка запускается автоматически из pre-commit хука
(`.githooks/pre-commit`). Включить хуки после клона:

```sh
git config core.hooksPath .githooks
```

## Установка

Открой целевой проект своим кодинг-агентом, дай ему этот каталог как источник
и файл [`ONBOARD.md`](ONBOARD.md) как инструкцию — агент проведёт разведку,
короткое интервью, разложит дистрибутив и запишет манифест установки. Ни
внешнего движка, ни рантайма не нужно: airules — standalone-дистрибутив.
Ссылки на опциональный софт, который подключают правила и оверлеи (OpenSpec,
rtk, тулчейн 1С), — в [`SOFTWARE.md`](SOFTWARE.md).

## Что внутри

Правила, навыки, роли субагентов и команды. Актуальные числа и полный перечень с
раскладкой в целевом проекте, хуками, контуром памяти и списком софта —
[`docs/INVENTORY.md`](docs/INVENTORY.md).

Адаптация общих навыков и процедур тестирования 1С, их границы с pipeline,
раскладка для Claude/DSH и результаты проверок описаны в
[`docs/AIRULES-SKILLS-INTEGRATION.md`](docs/AIRULES-SKILLS-INTEGRATION.md).

Готовые слои: роутинг ролей и моделей (`core/agents`, `core/install`),
модельные профили поведения (`core/install/model-profiles.md`), контракты
скриптов и COM (`core/rules/script-contract.md`, `overlays/1c/`), интеграция
OpenSpec (`core/rules/sdd-integrations.md`, `project-template/openspec/`),
раскладка (`core/install/layout.md`) и инсталлятор (`ONBOARD.md`
+ `core/templates/AGENTS.md`, синхронизация по манифесту — `docs/SYNC.md`).
Тела правил и ролей ядра — на английском (языковая политика —
`docs/CONTRIBUTING.md`).

Вне дистрибутива: [`services/1c-facade/`](services/1c-facade/README.md) —
MCP-фасад для 1С. Шесть глаголов вместо зоопарка серверов с пересекающимися
инструментами, маршрутизация выведена из замеров, реестр конфигураций и карта
здоровья парка. Запускается в docker, подключается одной строкой в `.mcp.json`.

Дальше: доперевод оставшихся русскоязычных файлов (см. `docs/TODO.md`) и
контент overlays следующими этапами, каждый — через входной фильтр
(`docs/LAYERS.md`).
