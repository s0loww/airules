# airules

**airules** — чистый дистрибутив методологии AI-разработки: правила, роли,
роутинг моделей и канальные адаптеры, собранные в переносимую слоистую модель.
Это **не форк** какого-либо рабочего репозитория правил — это новый проект,
куда каждый артефакт попадает только пройдя входной фильтр сорта: практика
включается в дистрибутив, если она действительно переносима, а не потому, что
она уже где-то написана.

## Слоистая модель

Дистрибутив разделён на три слоя по степени переносимости:

- **`core/`** — generic-метод без доменной специфики: роутинг ролей и моделей,
  контракты скриптов, принципы делегирования, структура agent definition.
  Переносится в любой проект любого стека.
- **`overlays/<stack>/`** — специфика технологического стека (не проекта).
  Переносится между проектами одного стека.
- **`project-template/`** — шаблон проектного слоя: описывает, что остаётся в
  целевом проекте и никогда не попадает в дистрибутив (пути, доменные имена,
  креды, память).

Полные определения слоёв и входной фильтр — в [`docs/LAYERS.md`](docs/LAYERS.md).

## Синхронизация

Модель распространения — **релизы + манифест установки**: дистрибутив живёт в
этом репозитории, версии помечаются git-тегами и файлом `VERSION` (semver).
Агент-инсталлятор копирует выбранные слои в целевой проект и записывает
`.airules-manifest.json`, по которому потом выполняется безопасное обновление.
Подробности — в [`docs/SYNC.md`](docs/SYNC.md).

## Чистота слоёв

Чистота слоёв контролируется CI: скрипт `ci/check_layers.py` ищет утечки
кредов, машинных путей, доменных имён, стековых терминов в ядре и хардкода
моделей. Проверка запускается автоматически из pre-commit хука
(`.githooks/pre-commit`). Включить хуки после клона:

```sh
git config core.hooksPath .githooks
```

## Статус

Этап 1 — скелет репозитория плюс слой роутинга моделей. Контент overlays и
проектных практик приходит следующими этапами, каждый — через входной фильтр.
