Turn the error investigation that just finished into one durable record.

Invoked by the user at the moment the investigation is complete — that is the
trigger this command exists to provide. Do not run it on your own initiative,
and do not run it mid-investigation: a record written before the cause is
confirmed stores a hypothesis as if it were a finding.

## Rules

1. **Refuse to invent.** Build the record only from what happened in this
   session. If the cause was never confirmed, or the fix was not verified, say
   so plainly and record it as an open case with the state it actually reached
   — an investigation recorded as closed when it is not is worse than no
   record, because the next session trusts it.

2. **Shape — all six parts, in this order.** Omit a part only when it is
   genuinely empty, and say which one you omitted.
   - **Symptom** — how it showed up, verbatim where possible: the error text,
     the failing command, the observed behaviour. This is the search key: the
     next person arrives with the symptom, not with the cause.
   - **Cause** — what it actually turned out to be, not the first hypothesis.
   - **Fix** — what was done, with paths.
   - **Why the obvious answer failed** — only when a plausible solution was
     tried and did not work. This is the part that saves the most time later.
   - **Dead ends** — what was attempted and abandoned, each with the reason.
     A dead end is a reason not to repeat an attempt; without the reason it is
     just a list.
   - **How to recognise it next time** — the earliest signal that this is the
     same case.

3. **Never record** the diff, the list of changed files, the sequence of tool
   calls, or a narrative of the session. The repository already carries those,
   and a second, staler copy is exactly the failure the memory layer is meant
   to avoid. Record the knowledge, not the transcript.

4. **Route it once** (`case-book` routing table):
   - specific to this project — its data, its integrations, its history →
     the memory server, when the project has one wired; otherwise the project
     case book named in the root contract;
   - generic for the stack — anyone on this technology hits it → the case book
     of that stack's overlay **in the distribution**, so it ships to every
     project;
   - generic for any stack → a rule in the distribution core, not a case.

   One destination, never two. An entry written to both places becomes two
   half-current copies.

5. **Deduplicate before writing.** Search the memory server for the symptom
   first (`memory_hybrid_search` — keyword and semantic together; the same
   case is often worded differently). If a matching record exists, **update
   it** rather than create a second one: add the new evidence, correct what
   turned out to be wrong, and say in the response that you updated an
   existing record and what changed. `memory_absorb` performs this
   search-then-merge in one call and is the preferred path when the record is
   a plain fact; use it unless you need explicit control over the merge.

6. **Tags — from the allowlist, not invented.** Call `memory_tags` and pick
   from what it returns; the store's own namespaces already encode project and
   genre. Do not create a new tag to describe one record — a tag that applies
   to a single entry is a title, not a tag.

7. **Superseding.** When the record contradicts something already stored —
   a decision that has been reversed, a fact that has changed — mark the old
   entry as superseded rather than deleting it. The fact that a belief was
   held and abandoned is itself worth keeping; a silently deleted record looks
   like it was never true.

8. **No memory server and no project case book** — do not improvise a
   location. Say that routing is unconfigured, show the record you would have
   written, and let the user choose where it goes.

## Response

One short paragraph: what was recorded, where it went, and whether it created
a new entry or updated an existing one. If any part of the shape was omitted,
name it. No preamble, no restatement of the investigation itself — the user
just lived through it.
