# Реестр ролей

Канонический реестр generic-ролей субагентов. Модель не хардкодится ни в
роли, ни в agent definition — роль несёт только `tier`, а конкретная модель
резолвится по каналу через `core/channels/model-map.yaml` в момент установки.

Легенда `tools`: **ro** — чтение/поиск (без права записи); **rw** — то же
плюс запись файлов и запуск команд.

| role | tier | tools | override | назначение |
| --- | --- | --- | --- | --- |
| explorer | low | ro | — | Разведка кодовой базы, поиск, карта подсистем — без правок |
| doc-writer | low | rw | — | Пользовательская/административная документация, гайды |
| error-fixer | medium | rw | fast | Быстрый точечный фикс ошибок, минимальные правки без архитектурных изменений |
| developer | medium | rw | — | Реализация кода по готовому плану |
| metadata-manager | medium | rw | — | Работа со структурой/схемой данных и конфигурации |
| refactoring | medium | rw | — | Рефакторинг, удаление мёртвого кода, консолидация |
| tester | medium | rw | — | Тестирование, проверка поведения, деплой на тестовый контур |
| analytic | medium* | rw | — | Анализ, требования, спецификации (без написания кода); tier условный — см. «Условные тиры» |
| planner | high | rw | — | Декомпозиция задачи, план реализации, риски, зависимости |
| architect | high | rw | — | Архитектура изменения, дизайн компонентов, план сборки |
| arch-reviewer | high | ro | — | Ревью архитектурных решений |
| code-reviewer | high | ro | — | Ревью кода — только по явному запросу пользователя |
| performance-optimizer | high | ro | — | Поиск узких мест, анализ производительности; правки отдаёт developer |

## Семантика override

`override` — опциональный per-role тир поверх базового. Сейчас определён
один: `fast` — дешёвый быстрый исполнитель для механических фиксов. Если
канал в `model-map.yaml` определяет тир `fast` — роль с таким override
получает его; если канал `fast` не определяет — роль работает на своём
базовом tier из таблицы выше. За счёт этого один реестр покрывает и каналы с
расширенным набором моделей, и каналы с минимальным набором.

## Условные тиры

Для роли `analytic` tier зависит от готовности входных данных:

- **medium** — данные предварительно подготовлены;
- **high** — аналитик работает по сырым источникам без предварительной
  подготовки.

Решение принимает оркестратор в момент запуска. Agent definition при этом не
меняется: инсталлятор кладёт базовый tier (`medium`), повышение до `high` —
параметр конкретного запуска.

## Принципы

- Маршрутизация строится на паре роль+tier, а не на имени конкретной модели.
- Финальные решения и интеграция результата — зона ответственности главного
  агента (оркестратора); выход субагента — рабочий материал, а не готовое
  решение.
- ro-роли не получают прав записи ни при каком канале и ни при какой
  конфигурации — расширение прав означает смену роли, а не смену настроек.
- Специализация под конкретный технологический стек оформляется оверлеями
  (`overlays/<stack>/agents/`). Оверлей наследует `tier` отсюда и не может
  задавать модель самостоятельно.
