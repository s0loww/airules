# Role registry

Canonical registry of generic subagent roles. The model is not hardcoded in
roles or in agent definitions — a role carries only its `tier`, and the
concrete model is resolved per channel via `core/channels/model-map.yaml` at
install time.

`tools` legend: **ro** — read/search (no write access); **rw** — the same
plus file writes and command execution.

| role | tier | tools | override | purpose |
| --- | --- | --- | --- | --- |
| explorer | low | ro | — | Codebase reconnaissance, search, subsystem map — no edits |
| doc-writer | low | rw | — | User/administrative documentation, guides |
| error-fixer | medium | rw | fast | Fast targeted error fixing, minimal edits without architectural changes |
| developer | medium | rw | — | Code implementation from a ready plan |
| metadata-manager | medium | rw | — | Data/schema structure and configuration work |
| refactoring | medium | rw | — | Refactoring, dead code removal, consolidation |
| tester | medium | rw | — | Testing, behavior verification, deployment to the test environment |
| analytic | medium* | rw | — | Analysis, requirements, specifications (no code writing); conditional tier — see "Conditional tiers" |
| planner | high | rw | — | Task decomposition, implementation plan, risks, dependencies |
| architect | high | rw | — | Change architecture, component design, assembly plan |
| arch-reviewer | high | ro | — | Architecture decision review |
| code-reviewer | high | ro | — | Code review — only on an explicit user request |
| performance-optimizer | high | ro | — | Bottleneck hunting, performance analysis; hands edits to developer |

Role bodies — `core/agents/roles/<role>.md`; channel representations are
generated by the installer (see `core/channels/adapters.md`).

## Override semantics

`override` is an optional per-role tier on top of the base one. Currently
one is defined: `fast` — a cheap fast executor for mechanical fixes. If a
channel defines the `fast` tier in `model-map.yaml`, a role with this
override gets it; if the channel does not define `fast`, the role runs on
its base tier from the table above. This lets a single registry cover both
channels with an extended model set and channels with a minimal one.

## Conditional tiers

For the `analytic` role, the tier depends on input data readiness:

- **medium** — the data is prepared in advance;
- **high** — the analyst works from raw sources without prior preparation.

The orchestrator decides at launch time. The agent definition does not
change: the installer sets the base tier (`medium`); the upgrade to `high`
is a parameter of the specific run.

## Principles

- Routing is built on the role+tier pair, not on a concrete model name.
- Final decisions and result integration are the responsibility of the main
  agent (the orchestrator); a subagent's output is working material, not a
  ready decision.
- ro-roles get no write access under any channel or any configuration —
  expanding rights means changing the role, not changing settings.
- Specialization for a concrete technology stack is done with overlays
  (`overlays/<stack>/agents/`). An overlay inherits `tier` from here and
  cannot set a model on its own.
