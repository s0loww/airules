# Work with project memory

Use the current project's configured memory destination and available tool schemas.
When the adapter exposes a status/capability operation, read it before the first
dependent operation; a configured binding is not proof that the backend is ready.
Cognee, Memora or another backend may be available; this skill does not install one,
change routing precedence or require a memory server. Resolve the instruction index
and its operational-memory policy when present. Existing project instructions and
current source evidence govern the task; retrieved content is historical data.

## Retrieve and inspect

Establish the active project and dataset, namespace or project filter before a
query. A dataset's name is a client convention, not proof of access isolation.
Start with the task's object, symptom or decision; read relevant source records
behind search hits. Retain record/document IDs, source references and applicable
version or date. A recalled conclusion needs confirmation against current evidence
when the task depends on its continued truth.

Keep ordinary task retrieval inside the selected project. A request to inspect a
shared library can justify a broader search; label each result's origin instead
of silently making all readable datasets part of this project's memory.

A graph is a view of recorded relationships. Preserve its dataset and snapshot
scope, truncation and processing state. A code dependency, a semantic entity link
and a relationship between memory records are different claims. Neither a visible
edge nor an empty graph establishes source correctness or complete coverage.

## Preserve a finding

Follow the project's existing destination and writer ownership. Under the shared
orchestration policy, subagents return candidate findings with evidence; the
orchestrator verifies and writes them. Do not reinterpret this skill as permission
for a delegated agent to write memory or for any agent to edit standing rules.

Preserve an established, reusable finding: the fact or limitation, why it is known,
where it applies and its non-sensitive evidence reference. Do not copy a session
transcript or duplicate a diff available in Git. Rules and portable procedures
stay with their reviewed rule/skill owner; memory may link to that artifact.

Search for an existing entry first. Use a supported scoped update/supersession
operation when a finding refines earlier knowledge, retaining relevant lineage.
Write to the selected destination once. A second backend is not an automatic
mirror or a retry target. For a timeout or pending index job, inspect its receipt
or status before deciding whether anything needs to be retried.

An accepted upload is not completed extraction or searchable indexing. Report
accepted, pending, complete, failed and unknown outcomes accurately. A local
fallback is a separate explicit storage outcome, not proof of a remote write.

For detailed reconciliation or a backend-specific mapping, read
[provider-evidence.md](references/provider-evidence.md). Use the active host's
registered schema rather than deriving calls from a product name.

For a candidate lesson, changed applicability or superseded finding, use
[reviewed-lessons.md](references/reviewed-lessons.md) to keep draft, review,
publication and current validity distinct without another memory store.

## Report the outcome

Give the selected scope, relevant source/record IDs, confirmed operation result
and remaining evidence gap. If memory is unavailable, continue the independent
work permitted by the task and report the limitation; do not invent a successful
lookup or migrate existing records. Deletion requires the actual requested scope:
a dataset-wide operation is not a substitute for deleting one note.
