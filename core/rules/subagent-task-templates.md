# Шаблоны задач для субагентов

Использовать вместе с `subagents-model-routing.md`. Держать делегируемую работу
ограниченной, самодостаточной и полезной, пока главный агент продолжает
непересекающуюся работу. Tier каждой роли — по `core/agents/ROLES.md`;
конкретную модель канала подставляет инсталлятор.

**Обязательная первая строка каждого промпта субагенту:** «Выполняй задачу сам,
своими инструментами; не запускай других агентов и не жди фоновых процессов —
их у тебя нет; временные файлы — в `var/tmp/`; закончил финальный отчёт —
остановись.» Полный блок дисциплины — `core/channels/adapters.md` §4; в промпте
достаточно этой строки. Известный отказ без неё: субагент «запускает фоновую
задачу» и бесконечно ждёт несуществующего уведомления.

## explorer-impact

Роль: `explorer` (tier по ROLES.md).

Область: read-only.

Промпт:

```text
Read-only анализ влияния. Рабочая копия: <path>. Найди все локальные ссылки на
<объект/процедуру/реквизит>. Сначала текстовый/локальный поиск; поиск по коду
профиля проекта — только для навигации/контекста, если доступен. Источник истины
текущего кода — локальный источник проекта. Файлы не править. Верни: файлы со
ссылками на строки, категории вызовов/использований, рискованные зависимости и
пробелы.
```

## explorer-patterns

Роль: `explorer` (tier по ROLES.md).

Область: read-only.

Промпт:

```text
Read-only поиск паттернов. Рабочая копия: <path>. Найди существующие реализации,
похожие на <задачу>. Предпочитай локальный источник истины и правила проекта.
Файлы не править. Верни: 3-7 лучших примеров с путями/строками, какой паттерн
переиспользовать и что не копировать.
```

## metadata-scout

Роль: `metadata-manager`, read-only (tier по ROLES.md).

Область: read-only.

Промпт:

```text
Read-only разведка метаданных/форм. Рабочая копия: <path>. Осмотри <объект
метаданных/форму/макет>, используя локальный XML/код проекта как источник истины.
Файлы не править. Верни: структуру объекта, элементы/команды/события формы,
связанные модули, риски валидации и предлагаемую область записи.
```

## worker-bounded-edit

Роль: `developer` / `metadata-manager` / `error-fixer` (tier по ROLES.md; у
`error-fixer` действует override `fast`, если канал его определяет).

Область: писать только явно назначенные файлы.

Промпт:

```text
Ограниченная реализация. Рабочая копия: <path>. Ты не один в кодовой базе; не
откатывай и не перезаписывай правки вне своей области. Правь только: <файлы>.
Реализуй <конкретное изменение>. Следуй правилам проекта. Запусти релевантные
локальные проверки, если доступны. Верни: изменённые файлы, сводку, проверки и
любой нерешённый риск.
```

## reviewer-risk

Роль: `code-reviewer` / `arch-reviewer` (tier по ROLES.md).

Область: read-only.

Промпт:

```text
Независимое ревью. Рабочая копия: <path>. Отревьюй текущее изменение на баги,
регрессии, пропущенные проверки и нарушения правил проекта. Файлы не править.
Только высокоуверенные находки. Верни сначала находки со ссылками
файл:строка, затем пробелы в тестах и остаточный риск.
```

## smoke-check

Роль: `tester` или `explorer` (tier по ROLES.md).

Область: read-only, если не назначен запуск команд.

Промпт:

```text
Smoke-проверка. Рабочая копия: <path>. Убедись, что <фича/правило/инструмент>
обнаруживается и работает через штатные точки входа. Файлы не править. Верни
точные команды или вызовы инструментов, наблюдаемый результат и pass/fail.
```
