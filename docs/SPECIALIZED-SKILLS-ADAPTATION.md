# Специализированные навыки 1С: каноническая адаптация

Дата: 2026-11-07. Этот инкремент добавляет четыре специализированных навыка к
существующим 48 в составе DSH. Из итоговых 52 навыков 50 принадлежат core/overlay,
ещё два — только target DSH и не устанавливаются в Codex/Claude.
Исходники и проверки используют фикстуры; реальные хранилища,
ИБ, MCP-записи, публикация, обновление поставщика и deploy не запускались.

## Разделение владельцев

| Навык | Канонический метод | Условная деталь | Владелец исполнения |
|---|---|---|---|
| 1c-repository-manage | Привязка, точные объекты, владение lock, публикация и результат по объектам | references/operations.md | Доступный repository capability или проверенный проектный runner |
| 1c-ai-merge | Три подтверждённых входа, классификация изменений и отделение плана от применения | Логические правила extension-patterns и метаданных через активный индекс | Локальный planner и отдельно настроенный runner применения |
| v8unpack-cf | Различение обычной Form.bin и целого CF/CFE/EPF, сохранность и логический round trip | references/artifact-workflow.md | Поддерживаемый codec/CLI или проектный runner |
| 1c-element | Распознавание XBSL-поддерева и выбор реальных средств проверки | Проектные инструкции и родственные примеры | Штатные текстовые средства и фактически доступный Element-native tool |

Все четыре метода относятся к `overlays/1c/skills`, поскольку зависят от
технологии, но не конкретного проекта или хоста. Они не переносятся в generic
core. Имена сохранены для узнаваемой маршрутизации, тела написаны под нашу
оркестрацию и границы полномочий. Копий исполняемых скриптов донора нет.

Новые entrypoints имеют только native поля `name` и `description`, точные
триггеры и условную загрузку references. Они не требуют постоянной загрузки всех
четырёх навыков и не добавляют обязательный этап ко всякой задаче 1С. Тип/роль
в каталоге описаний не является разрешением операции.

## Что изменено относительно исследованного источника

Исследованы одноимённые SKILL.md из поставленного пользователем
`dsh-1c-bundle/skills`; команды и конфигурация коммерческой сборки не копируются
в канон и не объявляются нашими capabilities.

- **Repository:** сохранены object scope, частичный результат, чужие блокировки,
  freshness и разделение force/discard. Git commit/push не означает публикацию
  в хранилище. Bind/unbind и администрирование — отдельные задачи; они не служат
  автоматическим обходом конфликта. Верифицированные разрешения пользователя
  сохраняются, skill не вводит их обязательное повторное подтверждение.
- **AI merge:** отсутствуют donor-only `/merge1c`, `run: subagent`, `1c-*`
  provider, `yolo` и `/rewind`. План, CFE-предложение и реальное применение имеют
  разные результаты. Два входа не выдаются за доказанное трёхстороннее слияние;
  extension strategy не обещает полноту обновления и миграции данных.
- **Binary:** ordinary form и whole container остаются разными маршрутами.
  Непрозрачные данные, исходный артефакт и manifest сохраняются; проверяется
  логическое содержимое. Наблюдения о старой версии codec не превращены в
  вечное ограничение всех версий. Пересборка не выдаётся за платформенную приёмку.
- **Element:** распознавание ограничивается подтверждённым поддеревом mixed
  проекта. Отсутствующий XBSL tool считается ненастроенной возможностью, а не
  вечным запретом среды. Classic 8.x инструменты не объявляются XBSL-валидаторами;
  SDK, credentials и публикация не устанавливаются как побочный эффект.

## Граница DSH

Конкретный условный контракт находится в
[`targets/dsh/contracts/onec-specialized.md`](../targets/dsh/contracts/onec-specialized.md).
Он описывает зарегистрированный `airules_onec_specialized`, проектные bindings,
saved plans и versioned runners. В portable skills конкретное имя этого tool
не требуется: другой target может предоставить эквивалентный project runner.

Чтение сохранённого repository report не выдаётся за live-query. Локальные
hash/artifact diff и CFE proposal не являются выполненным обновлением. Фасад
MCP не обязателен. Обычная регистрация skill или сохранение конфигурации не
даёт доверия к runner и не меняет native sandbox/approval/target guards.

## Проверка

Четыре entrypoint прошли `quick_validate.py` с локальным UTF-8 режимом Python.
Установочные тесты расширены четырьмя именами: они проверяют фактическую раскладку
всех файлов каждого bundle в Claude и DSH, а embedded тест сопоставляет полный
инвентарь с исходниками и SHA. `docs/INVENTORY.md` генерируется из установки,
а не правится вручную.

Для опасных веток предусмотрен независимый forward-testing на одноразовых
материалах: repository conflict/partial outcome, неполные merge-входы, различение
Form.bin и whole CF, mixed Element/BSL. Он не требует реальных репозиториев,
платформы, доступа к ИБ или разрешения публикации.

Runtime DSH и протокол project runner проверяются в репозитории интеграции,
отдельно от проверки Markdown и механической раскладки. Наличие skills в
embedded package подтверждает доступность инструкций, а не наличие конкретного
repository или binary backend у получателя.

Механические результаты этого прохода: 4/4 quick_validate, 38 unittest cases OK,
`check_layers.py` exit 0, `check_composition.py` PASS для Claude/DSH/Codex,
симуляция установки и обновления инвентаря 19/19. После добавления навыков
удалено фиксированное число 46 из теста Codex: manifest count теперь сверяется
с фактическим canonical inventory, присутствие четырёх новых имён проверяется
явно. Разница 50 portable skills и 52 embedded DSH сохранена тестами исключения
двух DSH-only помощников из Claude/Codex.

Логи расположены в `var/specialized-*.log`. Независимый поведенческий проход и
native runner acceptance имеют собственные отчёты интеграции; они не заменены
прохождением этих механических тестов.
