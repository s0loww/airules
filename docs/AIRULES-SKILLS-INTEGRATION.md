# Интеграция принятого комплекта навыков в airules

Дата: 2026-11-05. Проверены исходники и сборки на изолированных фикстурах;
рабочие проекты, MCP, модельные вызовы и deploy не запускались.

## Владелец метода и границы

Канонический источник — этот репозиторий. Переносимые инструкции находятся в
`core/skills`, специфика тестирования 1С — в `overlays/1c/skills`. DSH получает
собранные файлы через target, без собственной изменяемой копии метода.
Проектный контекст, пути, runner-команды и подключения остаются у проекта или
машины получателя. Навык не создаёт доступ, сервис, тестовый framework или
зарегистрированный инструмент своим названием.

| Навык | Канонический слой | Что сохраняется общим | Что определяется средой/проектом |
|---|---|---|---|
| handoff | core | Передача текущего состояния, evidence и следующего шага | Место записи и существующая система памяти |
| skill-maintainer | core | Выделение повторяемого метода из проверенного опыта | Формат target и доступные средства проверки навыков |
| security-baseline | core | Адресный анализ границ доверия и существенных рисков | Стек, threat model и реальные интерфейсы |
| architecture-evolution | core | Совместимость, миграции и сохранение поведения | Архитектура и ограничения конкретного проекта |
| technical-debt | core | Доказательный поиск долга и его практических последствий | Принятый backlog и владелец решения |
| 1c-business-tests | overlays/1c | Тест бизнес-поведения, проверяемый результат и cleanup | Framework, runner и разрешённый тестовый контур |
| 1c-ui-regression | overlays/1c | Воспроизводимый пользовательский сценарий и assertions | Web/тонкий клиент, скрытый рабочий стол и доступный драйвер |
| 1c-verify-project | overlays/1c | Проектная процедура проверки с evidence и границами | Doctor/analyze/test/deploy bindings и реальные capabilities |

Общий pipeline, правила делегирования и verification gate остаются владельцами
процесса. Навыки дают адресные процедуры, а не новый обязательный pipeline или
повторное ревью каждой правки. Ссылки на правила используют логические ID и
доступный проекту индекс; пути исходного дистрибутива и несуществующие команды
донора не требуются. Дополнительные ресурсы остаются внутри своего skill bundle.

Подробности адаптации и provenance:
[общие навыки](GENERAL-SKILLS-ADAPTATION.md),
[тестовые навыки 1С](ONEC-TEST-SKILLS-ADAPTATION.md).

## Матрица раскладки

| Потребитель | Откуда берёт навыки | Проверенная раскладка | Граница утверждения |
|---|---|---|---|
| Claude target, стек 1С | core + overlays/1c | `.claude/skills/<name>/` со всеми ресурсами | Симулятор исполнил процедуру установки в одноразовый каталог |
| DSH project target, стек 1С | core + overlays/1c | `.dsh/skills/<name>/` со всеми ресурсами | Проверены staging, collision guard, apply/backup/rollback на фикстурах |
| DSH embedded 1С | Та же функция копирования target | `skills/<name>/`, manifest SHA и native frontmatter | Собран и проверен пакет из 22 навыков без проектных подключений |
| DSH Python/sysadmin | Пять generic core skills из проверенного embedded пакета | Отдельный provider состава соответствующего пресета | Native scope, загрузка, переключение и проектный приоритет проверены в overlay DSH |
| Другие среды | Канонические core skills | По поддерживаемой установке/target | Их native runtime в этом инкременте не запускался |

Имя навыка в YAML должно совпадать с именем каталога: native discovery и точный
вызов используют одно имя. DSH renderer теперь проверяет это до копирования.
Новые native skills имеют `name` и `description`; DSH-only frontmatter для
вызова donor subagent или фиксированного набора MCP не переносится.

Каталог содержит короткие descriptions. Тела навыков и references загружаются
по запросу. Назначения DSH по типам задач/ролям остаются target-метаданными;
они не добавляются в generic core как разрешения или глобальные инструкции.

## Что изменено в механике

Сборщики уже динамически обходили каталоги навыков: отдельного allowlist или
второго renderer не потребовалось. В embedded тесте фиксированное число 14
заменено инвентарём исходников; наличие именно восьми новых адаптаций проверяется
отдельно. Проверка раскладки сопоставляет все файлы каждого нового bundle между
исходником, Claude и DSH, включая дополнительные references и NOTICE.

Для достоверных результатов Windows CI дочерние Python-проверки composition
получают `PYTHONIOENCODING=utf-8` в окружении своего subprocess. Глобальные
настройки окружения не меняются. В шести ранее созданных Python/sysadmin rules
добавлены только `description` и `kind: process`; содержимое правил сохранено.

README отсылает за актуальными числами к генерируемому `INVENTORY.md`, чтобы
один список навыков не расходился с другим. Версия канонического релиза
`VERSION` не изменялась; новые файлы входят в development snapshot до релизного
коммита/тега по обычному процессу проекта.

Независимый forward-testing восьми навыков выявил конфликт в прежнем правиле
владельца: принимающая сессия должна была повторно запросить уже подтверждённое
разрешение. Исправлен только раздел приёма в
[`session-handoff`](../core/rules/session-handoff.md). Явные инструкции пользователя
и разрешения из активного разговора либо доверенного runtime сохраняются.
Запись handoff сама по себе не предоставляет разрешений; если она — единственное
свидетельство для существенного действия, источник проверяется до действия.
Неопределённость разрешается перед зависимым шагом, независимая разрешённая
работа продолжается. История рабочего дерева не откатывается к снимку.

## Проверки и артефакт

- `python -m unittest discover -s ci -p 'test_*.py'`: 13 тестов, OK.
- `python ci/check_composition.py`: PASS, оба объявленных target/profile состава.
- `python ci/check_layers.py`: exit 0, нарушений нет.
- `python ci/check_layers.py --selftest`: SELFTEST PASS.
- `python ci/simulate_install.py --emit-inventory`: 19/19; инвентарь обновлён.
- `python targets/dsh/rulepack/build.py --source . --output var/rulepack/airules-0.12.0-skills2 --version 0.12.0-skills2`:
  development artifact: 22 навыка, 55 правил, 13 ролей, 321 файл.
- `python targets/dsh/rulepack/verify.py --output var/rulepack/airules-0.12.0-skills2`:
  PASS, SHA и инвентари совпали.

Логи находятся в `var/skills-integration-*.log`, а симуляция обновления инвентаря
— в `var/skills-inventory-simulation.log`. Пакет фиксирует `source.dirty: true`;
он не выдаётся за чистый tagged release. Проверки подтверждают раскладку и
согласованность контрактов. Независимые поведенческие прогоны выполнялись отдельно
в одноразовых рабочих каталогах; их артефакты и сводный отчёт принадлежат частному
репозиторию интеграции `dsh_harness_overlay`, а не распространяемому канону.
Предыдущий snapshot `airules-0.12.0-skills1` сохранён; `skills2` включает исправление
правила приёма handoff. После исправления повторно прошли 13 тестов, layers и
composition, пакет повторно собран и проверен в новом каталоге.

Интеграционный пакет DSH policy dev31 установлен поверх UI dev15. В частном
репозитории интеграции прошли 456 тестов и 300 нативных проверок, включая
изоляцию четырёх пресетов, загрузку навыков, приоритеты, переключатели,
назначения и сохранность лицензий при импорте. Независимый offline проход
выполнил восемь предметных сценариев и две ветки приёма handoff. Он не заменяет
live-проверку конкретной базы, framework или UI target. Реальные runners, MCP,
COM и deploy в этих проверках не запускались. Сертификат установки и подробные
доказательства находятся у владельца DSH-интеграции; проектные подключения в
канон не добавлялись.
