# Адаптация навыков тестирования 1С

Дата: 2026-11-05. Добавлены три переносимых навыка в оверлей 1С:
`1c-business-tests`, `1c-ui-regression`, `1c-verify-project`.

Это заново сформулированные инструкции для airules по результатам сравнения
процедур сборки Олега с нашими правилами, а не копия его runtime или полного канона.
Исполняемые скрипты, `.dt`, MCP-конфигурация и зависимости не переносились.

## Входной фильтр и владелец политики

| Вопрос | Решение |
|---|---|
| Работает без изменений в любом стеке? | Нет: проведение, движения, роли/RLS, формы и каналы 1С имеют предметную специфику. |
| Работает в разных проектах 1С? | Да: конкретные runner, target, права, fixtures и процессы берутся из проектного контракта. |
| Требует конкретного получателя/DSH? | Нет: навыки загружают правила по stable ID и используют реально доступный канал; фасад факультативен. |

Слой — `overlays/1c/skills`. Проектные значения и конкретная recipe остаются
в проекте. Runtime DSH отвечает за разрешения, каталог и запуск, не за изменение
смысла навыков. Смысл verification/deploy остаётся у существующего pipeline и
проектного runner, а не у нового параллельного регламента.

## Сопоставление

| Навык | Взятая практика | Адаптация и граница |
|---|---|---|
| 1c-business-tests | Сохранённые проверки с независимыми expected/actual, реальный framework/runner, fixture ownership | Используется уже существующий engine; unit отделён от сценария с ИБ. Нет нового обязательного suite или named MCP. Сохраняются наши target guards, эффекты setup/teardown и статусы неизвестного исхода. |
| 1c-ui-regression | Повторяемый сценарий, проверенные locators, машинный failure, раздельные author/run | Web/Vanessa выбираются из развёрнутых каналов проекта. Hidden desktop — по нашему testing-1c; не подменяется foreground automation. Metadata не считается готовым DOM locator. Нет автоустановки Playwright или обязательного нового framework. |
| 1c-verify-project | Проектная recipe с инвентарём features, entry points, evidence и lifecycle | Существующий runbook/verify является владельцем. Нет требования всегда restore/deploy перед проверкой, нет жёсткого `.dev.env`, agent-browser или фиктивных onec_* commands. Draft/source-only не объявляется live-verified; сохранены locks/recovery и различие target/source/applied. |

Навыки используют наши `test-model`, `test-discipline`, `verification-matrix`,
`testing-1c`, `unit-tests-1c` и существующий tester-role contract. Они не делают
tester или code-reviewer обязательным после каждой правки. Общий цикл и бюджет
повторных проверок остаются в правилах оркестрации.

## Намеренно не перенесено

- «Роль ИБ — только информативная метка»: у нашего исполнителя есть отдельные
  ограничения на цель, среду, точный build и операции.
- Обязательный facade, прямые donor MCP-имена и команды его full-пресета.
- Универсальные обещания о серверных базах, hidden desktop или паролях: поддержка
  определяется реальным runner. TestEnv unit может создавать/применять ИБ.
- Отождествление preview/doctor с отсутствием эффектов: запуск процесса,
  credential references и запись отчёта могут требовать отдельных прав.
- Restore/stop shared services/cleanup без run ownership или разрешения.
- Переход статуса в live-verified по одному compile/deploy/fixture результату.

## Источники и происхождение

Сравнены `skills/1c-business-tests/SKILL.md`, `skills/1c-ui-regression/SKILL.md`
и `skills/1c-verify-project/SKILL.md` сборки Олега, а также её дополнительные
`1c-ui-regression/docs/regression-stand.md` и
`1c-verify-project/references/recipe-template.md`. Исходные тексты и команды
не воспроизводятся; лицензия донорского корневого пакета здесь не предполагается.

С нашей стороны прочитаны tester, правила тестовых слоёв и platform traps,
hidden-desktop контракт, workflow core/profile/runner contracts. Никаких живых
прогонов 1С, COM, MCP, runners или deploy эта адаптация не выполняет.

## Проверка артефактов

Три навыка прошли штатный `quick_validate.py` из skill-creator. На Windows
валидатор запущен с `python -X utf8`, поскольку его чтение без явной кодировки
на локальной cp1251 не декодирует UTF-8 корректно. Targeted layer scan по четырём
файлам навыков/шаблона нашёл 0 нарушений. Полная сборка, раскладка и независимый
поведенческий проход проверяются отдельно при интеграции комплекта.
