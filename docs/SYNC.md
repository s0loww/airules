# Синхронизация дистрибутива

Выбранная модель распространения — **отдельный репозиторий + релизы + манифест
установки**. Решение принято; `git subtree` описан ниже как опция, а не как
дефолт.

## Версии

Дистрибутив = этот репозиторий. Версии помечаются git-тегами `vX.Y.Z` и
дублируются в файле `VERSION` (semver). Пока без remote — репозиторий локальный.

## Установка

Агент-инсталлятор копирует выбранные слои в целевой проект и записывает в его
корень `.airules-manifest.json`:

```json
{
  "version": "<из VERSION дистрибутива>",
  "installed_at": "<ISO-8601 timestamp>",
  "files": { "<relative-path>": "<sha256>" },
  "placeholders": { "<PLACEHOLDER>": "<заполненное значение>" }
}
```

Установка без записи манифеста **запрещена**: без манифеста последующее
обновление невозможно. Секреты в `placeholders` **не пишутся** (ONBOARD §8).

Алгоритм хеша — **SHA-256 от байтов файла как есть** (без нормализаций
содержимого), hex в нижнем регистре, 64 символа. Эквивалентные команды:
PowerShell `Get-FileHash -Algorithm SHA256`, Python
`hashlib.sha256(open(p,'rb').read()).hexdigest()`.

**Следствие: переводы строк обязаны быть зафиксированы.** Раз хеш берётся от
сырых байтов, любая подмена переводов строк ломает сверку. При
`core.autocrlf=true` (дефолт git для Windows) и без `.gitattributes` в цели
checkout переписывает LF на CRLF — и обновление видит изменённым **каждый**
управляемый файл. Поэтому установка кладёт в корень цели `.gitattributes` из
`project-template/gitattributes.example` (ONBOARD §4.1), пиная текст в LF, а
`*.ps1` в CRLF, и покрывает только управляемые пути. Проверка — `git
ls-files --eol`: колонка `w/` обязана совпадать с тем, что предписывает
`attr/`.

## Обновление

Для **копируемых как есть** файлов инсталлятор сверяет sha256 каждого
установленного файла с манифестом:

- **не изменён пользователем** → заменить новой версией из дистрибутива;
- **изменён пользователем** → спросить: оставить как есть или перезаписать, сняв
  бэкап в `.rules-backups/<timestamp>/`;
- **новый файл в дистрибутиве** → добавить; новое **правило** дополнительно
  вносится в Rule Index пересборкой листингом (ONBOARD §4.2) — независимо от
  того, менялся ли шаблон `AGENTS.md`;
- **удалён из дистрибутива** → предложить удалить у пользователя.

Три класса файлов sha-сверкой **не** обновляются (полная процедура — ONBOARD §9):

- **Генерируемые файлы** (`AGENTS.md`, `openspec/project.md` — параметризованы
  фактами целевого проекта): «версии из дистрибутива» у них не существует, их
  «источник изменился» определяется по диффу шаблона-источника между версиями
  дистрибутива. Шаблон изменился → обновить **слиянием**, сохранив заполненные
  факты; не изменился → не трогать.
- **Рендер-добавки раскладки** (стандартные блоки, которые инсталлятор добавляет
  в agent definitions при рендере — см. `core/install/layout.md`):
  если между версиями изменились правила рендера, а не тела ролей —
  переприменить рендер, тела ролей не трогая.
- **Отрендеренные agent definitions** (`.claude/agents/*.md`): «версии из
  дистрибутива» у них тоже нет —
  они продукт рендера тел ролей. Если между версиями изменились сами тела
  ролей или их tier/effort/tools в реестре → **перерендерить** затронутые
  определения по процедуре установки (тело + блок дисциплины + профиль
  модели); локальные правки пользователя ловятся манифестом и решаются общей
  развилкой (спросить, бэкап). Тела не менялись → не трогать.

В конце обновления манифест **переписывается**: новый `version`, свежий
`installed_at`, пересчитанные `files`, актуальные `placeholders`.

### Обновление на 0.8.0

Две темы: факты боевой раскатки, доехавшие в правила оверлея, и появление
каталога `services/` рядом со слоями.

- **`services/` — не слой и в цель не едет.** Инсталлятор его не видит:
  сервисы (в том числе MCP-фасад 1С) запускаются на машине разработчика и
  обслуживают все её проекты сразу. При обновлении ничего оттуда не копировать
  — см. `services/README.md` и `docs/LAYERS.md`.
- **Новая библиотека** `overlays/1c/tools/rules-check/` — исполняемая проверка
  той части правил оверлея, которую можно проверить кодом. Ставится в
  `tools/rules-check/` тем же нормативным путём, что `com-tools` (ONBOARD §5),
  пути добавить в `.gitattributes` цели. Зависимость односторонняя: сервис
  фасада умеет её звать, сама она про фасад не знает и работает в pre-commit
  проекта без него.
- **Шаблон контракта:** в секции «MCP» появился буллет **Layer boundary**
  (конституция под git, операционный поток в сервере памяти). Обновлять
  слиянием; **сервер памяти в проекте не подключён — буллет удалить целиком**
  (ONBOARD §4.3).
- **Правила оверлея 1С обновлены фактами раскатки:** `com-powershell-1c`
  (сериализация типов расширений через внешнее соединение, веб-публикация
  держит файловую ИБ, BOM и тихая смерть интерпретатора), `dev-standards-core`
  (формат комментирования правок рефакторинга), `metadata-xml-workarounds`
  (новый раздел 11 — гейт компиляции форм внешних обработок),
  `getconfigfiles` (**починка**: рецепт выгрузки молча возвращал успех, теперь
  ожидание завершения конструктора и проверка кода возврата),
  `logging-strategy` (формулировка). Локальные правки пользователя в этих
  файлах ловятся манифестом и решаются общей развилкой.
- **Rule Index:** у `metadata-xml-workarounds` изменилось `description` —
  строку правила в индексе цели пересобрать, иначе новый класс симптомов
  («внешняя обработка не открывается») не найдётся.
- **Контур `agent-1c`:** пин BSL LS 1.0.3 → 1.0.7, помечен в `toolchain.lock.json`
  как **не проверенный чистым bootstrap** (sha из GitHub API, не из скачанного
  архива) — на первой установке с доступом к домену ассетов сверить и поправить;
  в шаблоне VAParams новый ключ `КаталогиБиблиотек`, подставляется скриптом.
- **Рендер ролей не нужен:** тела ролей, `ROLES.md` и `agent-template.md` не
  менялись.

### Обновление на 0.7.x — ломающее: остаётся один канал

Дистрибутив стал одноканальным: обслуживается только Claude Code, раскладки под
другие среды сняты. Для установок 0.6.0 и старше это самое крупное изменение за
всю историю обновлений — измеренный случай: **250 файлов из 414 (60%)** лежали в
`.codex/` и `.cursor/`.

- **Снятые каналы.** Их файлы попадают в штатную ветку «исчезло из дистрибутива →
  предложить удалить» (ONBOARD §9 шаг 3). Удалять молча нельзя: пользователь мог
  продолжать работать в этих средах и захотеть заморозить их на 0.6.0.
- **Плейсхолдеры.** `CHANNELS` сводится к `claude`, `CURSOR_MODEL_MAP` удаляется;
  таблица `{{AGENTS_TABLE}}` в `AGENTS.md` теряет колонки каналов.
- **`.gitattributes`.** Шаблон больше не несёт строк `.codex/**` и `.cursor/**` —
  при обновлении их убрать, иначе правила висят на несуществующих путях.
- **Переименование в дистрибутиве:** `core/channels/` → `core/install/`,
  `adapters.md` → `layout.md`. Ссылки в проектных документах поправить.

Кроме снятия каналов:

- **Rule Index пересобрать листингом и СГРУППИРОВАТЬ по жанру.** У правил
  появилось frontmatter-поле `kind` (`invariant` / `case` / `recipe` / `process`
  / `router`), индекс собирается группами, инварианты первой, внутри группы —
  алфавит (ONBOARD §4.2). В шаблон `AGENTS.md` добавлен абзац, объясняющий
  жанры, — обновлять слиянием. Проектным правилам, которых нет в дистрибутиве,
  `kind` проставляет установка: без него строка уходит в индекс без группы.
- **Новые правила:** `case-book` в ядре; в оверлее 1С — `access-rights-bsp`,
  `dcs-composition-recipes`, `kd2-exchange-rules`, `kd31-exchange-rules`,
  `unit-tests-1c`, `v8unpack-source-structure`.
- **Новая команда** `/разбор` (фиксация разбора ошибки, парная к `case-book`).
- **Гейт F** в `verification-matrix` — операционная память вокруг проверок.
- **Перерендерить только `developer` и `tester`** — менялись их тела. Шаблон
  `agent-template.md` правился лишь в комментариях (пути после переименования),
  tier/effort/tools в `ROLES.md` не менялись, поэтому массовый рендер не нужен.
- **Новая библиотека** `overlays/1c/tools/com-tools/` — ставится в `tools/`, в
  `.gitattributes` цели добавить её пути.
- **Хук напоминания правил** (`core/hooks/rule-inject.py` + карта оверлея) и
  **сервер памяти** (ONBOARD §4.2, §5.1, §4.3) — опциональные, ставятся по
  ответам интервью.

⚠ **Хук и pre-commit ищут интерпретатор по имени `python` в PATH.** На Windows
он часто установлен, но в PATH не выведен, а уже запущенные процессы не видят
свежедобавленный PATH до перезапуска. Симптом у хука правил — тишина вместо
впрыска; у pre-commit дистрибутива — `no usable Python found` и отказ коммита.
Лечение: прописывать в конфиге хука абсолютный путь к интерпретатору, а не имя.

### Обновление на 0.4.0 — ломающее изменение схемы

В 0.4.0 роль несёт не только `tier`, но и `effort`, а карта моделей получила
секцию `effort`. Установка версии 0.3.x и старше этих полей не содержит,
поэтому при обновлении **недостаточно** sha-сверки файлов:

- перерезолвить модель и усилие для КАЖДОГО агента и переписать поле `effort`
  во frontmatter;
- перегенерировать таблицу `{{AGENTS_TABLE}}` в `AGENTS.md` — у неё добавилась
  колонка `effort`;
- проверить, что ни у одного агента не проставлена верхняя ступень (`max`).

Это тот же класс операции, что и рендер-добавки раскладки: тела ролей не
трогаются, переприменяется рендер.

Заодно, если цель — git-репозиторий и `.gitattributes` в ней нет: положить
его из `project-template/gitattributes.example`, привести байты управляемых
файлов к конвенции (текст — LF, `*.ps1` — CRLF) и пересчитать sha. На
установках 0.3.x дерево обычно уже разъехалось, и без этого шага следующее
обновление упрётся в сплошное «изменено пользователем».

Если манифеста нет — обновление невозможно; допустима только переустановка с
предварительным бэкапом.

## Возврат практики в ядро

Практика, родившаяся в проекте, возвращается в дистрибутив так:

1. проходит входной фильтр (см. [`LAYERS.md`](LAYERS.md));
2. генерализуется — имена, пути и креды заменяются плейсхолдерами;
3. коммитится / оформляется PR в airules;
4. попадает в следующий релиз.

Проектный слой в дистрибутив **не возвращается никогда**.

## Опция: git subtree

Для тех, кто предпочитает вендоринг вместо инсталлятора, дистрибутив можно
подключить как `git subtree`: `git subtree add --prefix=airules <repo> <tag>
--squash`, обновление — `git subtree pull` на новый тег. Это осознанная
альтернатива, а не рекомендуемый путь: subtree не даёт манифеста, sha-сверки и
диалога о пользовательских правках, которые есть у инсталлятора.
