# Out of scope — база отклонённых решений

Институциональная память дистрибутива: что предлагалось, было осознанно
отклонено и почему. Две цели: не пережёвывать одно и то же повторно и дать
будущему ревизору контекст, чтобы отклонение можно было аргументированно
переоткрыть. Формат заимствован из mattpocock/skills (MIT).

## Формат

- **Один файл на концепт**, не на предложение: «ночная тема» и «тёмный
  режим» — один файл. Совпадение ищется по смыслу концепта, а не по словам.
- Структура файла: `# Концепт` → `## Почему вне скоупа` (свободная проза с
  примерами — короткий design-документ, а не строка в БД) → `## Прошлые
  предложения` (список: дата/источник + одна строка сути).
- **Причина обязана быть долговечной.** «Сейчас не до этого» — это отсрочка,
  а не отклонение; ей здесь не место.
- **«Уже реализовано» сюда не пишется** — это база *отклонённого*, а не
  построенного; реализованное живёт в правилах и CHANGELOG-е коммитов.

## Как пользоваться

- Перед предложением новой практики (и при триаже чужого предложения) —
  проверить эту папку по смыслу концепта.
- Совпадение найдено: либо подтвердить отклонение (дописать предложение в
  «Прошлые предложения»), либо осознанно переоткрыть — тогда файл
  обновляется или удаляется, а предложение идёт обычным входным фильтром
  `LAYERS.md`.
- Новое отклонение с долговечной причиной — новый файл сюда.
