# airules 0.17.0

Prepared: 2026-11-12. Previous version: 0.16.0.

## Changes

- Optional table-driven shell advisories for Codex and Claude: reviewed
  command/output literals select static hints. Registrations are opt-in and
  project configuration is never installed over an existing table.
- An opt-in 1C deployment advisory diagnoses the PowerShell `-File` /
  whitespace `-Dynamic "-"` trap. Optional process inspection remains
  target-scoped and read-only; hints do not authorize a deployment.
- Shared-checkout commits explicitly stage only task-owned paths. Content
  review uses the complete uncompressed diff.
- Verification starts with the existing project runner, bindings and
  revision-specific baseline instead of inventing a new environment.
- Version-scoped COM and DCS/XDTO diagnostic cases carry their observed
  applicability and limits. No new platform compatibility acceptance is
  implied by including the documented cases.

The rule library remains 55 rules. Accounting-engine interception,
traceability/control bypasses, concrete infobases and credentials stay in
the originating project. No role model map or MCP endpoint is changed.

## Upgrade

Follow [SYNC](../SYNC.md) and the selected target's renderer/installer.
Merge root contracts, retain project exceptions and preserve custom Bash
handlers. Enable the new feature only through reviewed bindings/settings
and a reviewed project table. Exact configuration and limitations are in
[COMMAND-ADVISORIES](../COMMAND-ADVISORIES.md).

DSH receives the portable policy through its rulepack build. This release
does not implement automatic DSH execution of Codex/Claude Bash hooks.

## Validation and release boundary

The release candidate is checked with assertion-based advisory tests,
registered-target event probes, layer/composition gates, Claude installation
simulation, Codex renderer/installer tests and a DSH rulepack build/verify.
The accompanying candidate receipt records exact results and artifact hashes.
Only results recorded there count as completed validation.

Candidate validation completed:

- 71 Python tests passed, including 18 advisory regressions and three
  registered-launcher integration tests.
- Layer purity, composition, hook routing and layer-checker self-tests passed.
- Claude opt-in simulation passed 19/19 checks; both Codex and DSH assemblies
  passed their verifiers.
- Native Codex discovery found 55/55 skills and parsed the hook/config layer
  in an isolated home. Native DSH package loading accepted 0.17.0 with 55
  rules, 13 roles and 53 skills. No model turn or live deployment was run.

The prepared candidate is built from a clean local release commit. The DSH
artifact is rebuilt with `--require-clean`; its source revision and file
hashes are recorded in the candidate receipt. Local preparation does not
create a Git tag or publish a remote release.

No live project rollout, production action, database query, service restart,
client hook-trust change, Git tag, push or remote publication is part of
preparing this candidate.
