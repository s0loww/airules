# project-template: шаблон проектного слоя

Это шаблон, а не контент. Он описывает проектный слой — то, что остаётся в
целевом проекте и **никогда не возвращается в дистрибутив** airules.

К проектному слою относятся:

- машинные пути (расположение баз, окружений, инструментов на конкретной машине);
- имена доменных объектов и доменные шаблоны кода конкретного проекта;
- креды — только через git-ignored `.env`, никогда в отслеживаемых файлах;
- проектная память (накопленный контекст, заметки, история решений).

Шаблон окружения для COM-скриптов 1С — [`env.example`](env.example): копируется
в целевой проект как `.env`, добавляется в `.gitignore` и заполняется реальными
значениями (в дистрибутиве — только плейсхолдеры).

Шаблон атрибутов git — [`gitattributes.example`](gitattributes.example):
кладётся в корень цели как `.gitattributes` (существующий не перезаписывается,
а дополняется). Фиксирует переводы строк управляемых файлов — без этого
`core.autocrlf` подменяет байты на checkout и sha в манифесте установки
перестают сходиться (подробности — `docs/SYNC.md`, ONBOARD §4.7). Имя в
дистрибутиве без точки специально: файл не должен действовать на сам
репозиторий дистрибутива.

Скаффолд воркспейса OpenSpec — [`openspec/`](openspec/): раскладывается в
целевой проект как есть (`README.md`, `config.yaml`, `project.md`,
`specs/README.md`, `changes/README.md`). `project.md` содержит плейсхолдеры
`{{...}}` и маркеры «НЕ НАСТРОЕНО» — заполняется фактами конкретного проекта
при установке или вручную; в дистрибутив реальные значения не возвращаются.

При установке дистрибутива инсталлятор заполняет проектный слой на стороне
цели, подставляя реальные значения вместо плейсхолдеров. Обратно в дистрибутив
этот слой не попадает: практика возвращается в ядро только после генерализации
(имена, пути, креды → плейсхолдеры) и прохождения входного фильтра из
`docs/LAYERS.md`.
